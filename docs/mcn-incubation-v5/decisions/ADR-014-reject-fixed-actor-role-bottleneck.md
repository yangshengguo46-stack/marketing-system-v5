# ADR-014：拒绝固定动作角色瓶颈，先校准金标

- 状态：已决定
- 日期：2026-08-14
- 依据：A45、A48、A49、E33、E34、ADR-013

## 决定

不注册 E34 的动作角色分析器与左右收敛器，也不把“完整对象 / 卖方操作或证明 / 买方普通使用 / 买方反复社会实践或结果”固化为 Lead 的必经分类。

关系优先和动作主体仍可作为离线检查视角，但下一步暂停继续加提示词。先把用户已经纠正过的案例整理成可审查标注协议，明确对象层级、需求为何成立、允许的替代根和真正错误的根，再用全新留出案例验证下一候选。

## 为什么不进生产

冻结门槛未通过：零合同失败，但关系仅 `3/4`、角色与处置 `11/16`、候选召回 `7/8`、最终收敛 `5/8`、最终对比 `2/4`。人工事实边界也失败。

唯一自动全过的饺子馅组是假阳性。左侧仍停在“川式饺子馅料”，没有回到完整的饺子世界；右侧选择了“北方饺子馅料”的 option id，却把 `audience_world` 改成“家庭饺子饮食偏好与长期餐桌选择”并错标为 `object`。评分器只因两者都包含“饺子”而通过。

婚礼请柬组更接近真正故障：模型已经召回婚礼筹备、宾客邀请和仪式沟通，却因过度保守把它标为条件候选，最终仍选请柬产品，没有完成从物件到其直接社会功能的跃迁。

输出还把儿童图书店扩成空间、社区、阅读推广、客流和复购，把皮鞋定制扩成量脚、选皮、手工制作、接单和交付周期，把饺子馅扩成生产、配方、采购、工厂、供应链与目标市场。部分被写进未知，但部分直接被拿来证明内容容量和回路。

## 为什么不能把冻结分数直接当真

E34 同时暴露了两个金标歧义：亲子共读确实可能是跨人物、跨场景反复发生的社会实践；手工定制也可能就是用户出售的完整服务，而不只是卖方能力证明。模型在这两题的部分判断有业务合理性，不能简单算成“模型不懂”。

因此四个角色适合提醒模型检查动作主体，却不适合做排他的固定标签。角色名称本身不能决定谁是内容根，仍要看对象层级、该实践是否构成需求、内容容量和返回业务的自然程度。

## 下一边界

下一候选运行前先建立小型、用户可复核的标注协议：

1. 原业务表达与来源对象。
2. 中间物、完整对象及其层级关系。
3. 卖方操作与买方普通使用。
4. 业务直接服务的人类需求或社会实践。
5. 可接受的多个内容根及其适用条件。
6. 明确拒绝的根，以及为什么是过宽、过窄、错主体或无回路。

水果、黄金礼品、海鲜、火锅底料、腕表和医美只作为开发证据，不再伪装成留出测试。新的离线评测必须使用用户未纠正过的新案例，并把“多个答案都合理”纳入合同，避免用一个武断金标惩罚正确联想。

## 后果

现役 Lead、`analyze_business_semantics`、`explore_content_worlds`、模型配置和 Gateway 均保持不变。E34 只保留为失败证据，不重跑、不微调、不拼接局部最佳，也不把四角色对象塞进每轮上下文。
