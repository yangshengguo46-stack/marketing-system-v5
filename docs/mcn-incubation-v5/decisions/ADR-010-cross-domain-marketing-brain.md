# ADR-010 跨行业营销脑候选架构

## 背景

黄金礼品专家锚点证明“商业表面 -> 品类行为 -> 人类任务 -> 内容领地 -> 商业归因”值得验证，但不能证明系统能服务水果店、果农、宝妈、品牌、服务和组织。第四版已经证明，把单案例洞察写成中心词 Schema、语义距离、固定故事协议和 Writer Brain 会形成新的语义控制层。

第五版必须在保留一个 DeerFlow Lead Agent 的前提下，既支持不同客户产生不同方案，又保存判断来源、替代方案、实际结果和修订原因。

## 候选决定

采用以下候选，接受条件满足前不接生产：

1. **唯一 Lead Agent** 保留孵化决策权，根据当前事实组合人物、商品、场所、生产源头和组织镜头；不按行业选择 Agent。
2. 稳定内核只要求候选解释人的任务、反复情境、主体拥有权、内容供给、商业归因和结果验证，不规定唯一语义路线。
3. 在现有 `IncubationDecisionVersion` JSON payload 内嵌轻量 `TerritoryCandidate`，保留多个候选与 `selected_territory_id`；不新增表和阶段状态。
4. 复用 `incubation_context` 按需返回方法与有来源知识，复用项目事实、证据和案例记忆；**不新增运行时**、重叠工具或第二 Agent 框架。
5. 核心提示词保持薄；先在隔离评测中比较基线、方法卡、方法加来源知识和 Lead 内发散收敛，再决定默认上下文。
6. 跨用户案例默认关闭；只有真实结果、人工复核、许可和脱敏条件都满足时才可成为共享候选。

## 明确不采用

- 每个行业一份提示词、Skill 或 `if industry == ...` 路由。
- 将所有行业、心理和文化概念预建成知识图谱或本体。
- 用中心词解析、语义距离或营销总分自动选择内容领地。
- 固定要求多个专家 Agent 发散、投票和审核。
- 在没有跨案例评测前进行微调、自动案例学习或向量数据库建设。
- 为了结构完整而拒绝信息不全的用户请求。

## 预期影响

- 同一表面标签可以因业务模式、主体能力、证据和目标不同而产生不同候选。
- 判断过程可追溯、可比较、可修订，但结构不会决定营销答案。
- 现有决策持久化可向后兼容扩展，减少新模块和迁移成本。
- 开放题仍存在模型不稳定和专家分歧，因此需要多次试验、人工校准与真实结果，不能靠单元测试宣布营销脑完成。

## 接受条件

- 黄金礼品、水果店、果农、宝妈以及至少若干品牌、单品、服务和组织案例完成人工锚点与反例复核。
- 相同模型和上下文预算下，候选架构在事实约束、领地深度、主体适配、商业归因和新证据修订上显著优于当前基线。
- 至少个人、门店/品牌和产品各完成一个真实“领地判断 -> 内容实验 -> 结果 -> 修订”闭环。
- 生产改动不包含行业路由、固定阶段、输出改写、语义评分门或强制子 Agent。
- 成本、延迟、跨用户隔离、来源追溯和模型升级回归均通过。

条件满足前保持 `proposed`。

## 2026-08-11 评测更新

A42 已实现不新增表的 `TerritoryCandidate` JSON 结构和隔离对照器，并完成 24 个密封试验、26 次模型调用。方法卡、自然回答、来源机制和两遍法均未通过完整业务验收；修正两遍法只在黄金锚点上部分产生“关系场景”语义，同时继续补造主体资产和经营数字。

因此本 ADR 不转为 `accepted`。领域结构保留为无生产入口的记录能力；评测方法卡、机制卡和两遍编排均不进入默认上下文，也不构成强制子 Agent。
