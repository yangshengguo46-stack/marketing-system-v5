# A21 第四版孵化失败根因审计

## 结论

第四版失败不是因为孵化方法不够多，而是把方法变成了互相叠加的控制系统。SOUL、通用提示词、首次使用中间件、策略方法、差异化、预演、复盘、自动晋升、工具白名单和轨迹测试都在决定 Agent 下一步必须做什么。

已提交历史给出了直接证据：

| 提交 | 删除规模 | 说明 |
| --- | ---: | --- |
| `4a81930a` | 1,677 行 | 删除首次使用、访谈、工具路由和编排门 |
| `879221e1` | 4,657 行 | 删除品牌、差异化、诊断和策略业务语义门 |
| `fc61bde6` | 15,415 行 | 退役 preflight、promotion、retro、cockpit 和遗留语义层 |

删除前的 `strategy_methodology.py` 强制九个阶段，从 `evidence_collecting` 到 `scaling`；第一版必须从首阶段开始，只允许原地修改或前进一步。进入后续阶段还强制：

- 人物必须提供年龄、性别、职业和地点语境；
- 影响、行为、经济三个目标必须各有条目并完整排序；
- 至少三个对标并覆盖商业模式、内容系统和身份表达三个角色；
- 定位候选必须恰好二至三个；
- 启动包至少三个名称、两个简介、三个置顶内容和三个试验；
- 商业信号和引用不满足时不能进入下一阶段。

这些字段单独看常有方法价值，但组合成运行时前置条件后，会让一个已有明确产品和证据的用户也必须补齐无关资料，使模型的自然判断和数据库状态机冲突。未提交救援代码继续增加写入校验和安全层，属于同一模式，不可迁移。

第四版仍有三类可吸收资产：

1. `ip-strategy-director` 审计后的方法：复用当前事实、主体与表达载体分离、证据与创意分离、给一个主方向和最小试验。
2. 用户事实、版本、幂等、所有权和观察结果的可靠性纪律。
3. 影响目标、行为目标和经济目标分开，以及专有事实加结果历史构成长期壁垒的研究。

## 第五版决定

- 不迁移第四版孵化生产代码、数据库阶段和未提交救援文件。
- 旧版只作为负面对照和方法来源，不成为第五版依赖。
- 所有业务对象允许信息不完整，并返回未知，不以完整度阻断判断。
- 测试只看业务结果，不固定工具轨迹、提问轮数、对标数量或内容数量。
- 版本、所有权和引用完整性可以硬约束；定位质量、创意和变现判断不能硬约束。
