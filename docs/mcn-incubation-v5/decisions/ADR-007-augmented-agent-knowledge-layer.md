# ADR-007 增强型孵化 Agent 与知识层

## 背景

真实预检和 `micro-bakeoff-20260810T152051Z` 证明，单靠修改 Lead Agent 核心提示词、增加 thinking 或塞入简短方法卡，不能稳定产出事实干净的孵化判断。该微型对照没有工具和真实项目状态，因此不能代表完整 Agent 架构。

## 提议

保留 DeerFlow 唯一 Lead Agent 和现有 LangGraph 运行时，增加四个类型隔离的只读上下文来源：

1. 来源化 MCN 方法库。
2. 用户与项目隔离的事实、证据、决策和结果账本。
3. 通过浏览器/MCP 获取并带时间与来源回执的外部证据。
4. 只含真实结果且经人工复核的项目内案例与反例。

项目状态写入、发布、费用和其他不可逆动作继续通过独立工具、所有权校验和人工批准。知识层只返回上下文，不改写模型输出、不强制固定阶段、不对营销判断设置分数门。

## 检索策略

首版使用元数据过滤加关键词/BM25，不引入向量数据库。只有离线检索评测证明 embedding 或混合检索显著改善召回和最终业务结果时才升级。通用 DeerMem 不作为项目业务真相源。

## 接受条件

- 生产和评测使用同一份孵化宪法及同一 Agent 工具面。
- 检索评测能够区分方法、项目事实、外部证据和案例，且跨用户/项目隔离通过。
- B01 等案例中的身份、产品效果、场地、渠道、产能和数字主张可以追溯到证据 ID，或明确保持未知/创意提案。
- 端到端评测观察真实工具调用和状态结果，而不只评单轮文本。
- 个人、品牌、产品各完成一个真实“判断、实验、结果、修正”闭环。

接受条件满足前保持 `proposed`，不得宣称外挂知识库已经解决孵化质量问题。

## 当前实现证据（2026-08-11）

- 生产与评测已共用单一孵化宪法。
- 十张方法卡、八条类型化来源和 12 条有界检索基线已测试。
- Owner 隔离的项目事实与项目证据只读工具已接入 DeerFlow；证据保存来源、时间、哈希、范围、局限、争议和有效期，但不会自动写成事实。
- 浏览器/MCP 采集写面、完整 Agent 工具轨迹评测和三个真实孵化闭环仍未完成，所以状态不变。
- A28 已补完整 Agent 评测运行器和离线密封轨迹测试；首次真实 `agent-eval-m01-v1` 因评测器的 12 图超步预算不足而在首个工具往返前失败，没有业务输出，仍不满足“完整 Agent 工具轨迹评测”的接受条件。
