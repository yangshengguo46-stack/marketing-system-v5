# A34 生产内容世界探索审计

## 结论

第五版此前并没有一个已验收的“内容世界生产能力”。E16 的地图、四坐标和选择器都是离线实验，因为会将宽品类压成购买教育、将内容世界压成人设，或把交易结构未知当成内容世界的反转条件而被拒绝。E17 接入的只是商业语义显化，它能读懂“黄金是材质、礼品是主词”，但不负责展开长期内容世界。

本轮首次把这个缺口做成默认 Lead 按需调用的有界工具 `explore_content_worlds`。它不选最终定位，只交付一张事实边界封闭、可供 Lead 收敛的内容世界地图。R2/R3 继续修正了 R1 的假设：语义主词不自动是内容根。现在必须分开商业对象、词法主词和最小完整内容根，再判断商品是可持续展开的完整对象、中间实现物，还是买方购买的专业任务。修饰词只有在拿掉后世界不完整、买方构成功能不保留或无法回到生意时才留在根中。火锅底料、海鲜、黄金礼品、水果和工业防护包装五种语义形状已完成当前合同的真实 Gateway 回归。

**这次通过的是“长期讲什么”这一层，不是整个营销脑已经 80 分。** 定位、人设、受众、表现形式、商业承接和后续实验仍需以真实主体信息继续验证。

## 标签来源边界

- 当前用户亲自提供并完成纠偏的人工金标只有 `4` 个：水果店、黄金礼品、海鲜和重庆火锅底料。
- 工业设备防护包装是系统补充的未见跨行业压力测试，状态为 `draft`。它的真实 Gateway 结果可以证明当前合同在一个专业任务样本上通过回归，但不能冒充用户标注。
- 因此本文的“五种业务形状通过”是工程验收计数，不是人工金标计数；任何后续数据蒸馏、评测统计或微调语料导出都必须保留这一区别。

## 为什么以前看起来“做了很久还没做出来”

1. **地图不等于生产能力。** E16-R4 能产出水果子世界，但它不在真实 Lead 工具列表中，用户聊天时根本不会调用。
2. **Lead 会把正确地图二次压窄。** R5/R6 已证明，即使上游给出季节、品种、产地等宽地图，Lead 仍会收敛成“懂水果的人”、社区店或供应链套路。
3. **选择器把直接交易结构当成唯一买方任务。** R7-R14 会用 B/C、代工或直接客户反过来推翻礼品的最终社会用途，使“交易结构”和“为什么被需要”互相冲突。
4. **仅加核心提示不能提供可观察中间产物。** 模型偶尔能答对，但失败时无法判断是语义主词、展开轴还是最终收敛出错。
5. **一次塞完整起号方案会转移模型注意力。** 当同一轮同时要求内容世界、B/C、平台、形式、承接和实验时，模型会为“完整”而补造行业常见角色和渠道。

## 生产架构

```text
真实用户消息
-> 商业语义显化（有界模型调用）
-> 根世界展开（有界模型调用）
-> 确定性 Schema 校验与事实投影
-> ContentWorldMap
-> 唯一 Lead 向用户做当前内容世界判断
```

### 工具输入

- 模型可见的工具参数为空，Lead 无法传入自己编写的业务总结。
- 工具只读取当前线程最近的真实用户消息，优先使用 `ORIGINAL_USER_CONTENT_KEY`；忽略 AI 消息、隐藏注入和模型改写。
- 用户原话超出有界长度时返回稳定错误，不截断后冒充完整事实。

### 内部展开

- 第一次调用区分经营载体、商业对象、语义主词、修饰、卖方动作、品类构成功能和买方进展。
- 第二次调用生成一张根地图，而不是三个竞争候选方案。地图显式包含种类与子世界、时间与历史、地理与环境、文化与生活习惯、人物、事件、冲突和跨领域待研究连接。
- 宽品类本身已有持续容量时保留完整对象世界；用途型组合可沿品类功能进入关系世界；专业服务可进入客户持续购买的任务或结果。
- 完整对象被选择、交换、消费或使用，并不因此自动变成更大行为的中间件；礼品仍是礼品根，送礼与人情属于向上连接。配方、原料、部件、工具或媒介若直接创造一个更完整、更宽且逐轴可归因的世界，才可升根；火锅底料因此进入火锅世界。
- 当语义同时明确被服务对象与专业目的时，将二者组成专业任务候选再比较；既不能只升成外部对象而丢掉业务关系，也不能只保留“包装”等泛词而丢掉买方结果。
- 修饰词的 `branch_lens | root_essential` 不由模型重复报标签：模型只报去词后世界完整性、买方构成功能与商业回路三项证据，代码唯一推导决定。材质或地域专属的工艺、参数或风味消失，不等于基础品类的买方功能消失。
- 跨国家、地区和文化群体的结构关系通过资源环境、规则禁忌、仪式社交、工具技法或历史传播机制判断；有机制却缺事例时保留为待研究问题，无机制时不强行凑轴。
- 具体历史、地域、制度和跨领域节点只是待研究方向，不是已核验事实；未浏览时不直接转述政策名、标准编号、历史断言或命名案例。

### 可靠性与隐私

- 两次内部模型调用共享 Lead 已授权的模型设置，不引入第二个 Agent 运行时。
- 原始思考不返回 Lead、不进入线程或工具产物；只记录脱敏的模型用量归因。
- 结构输出首次不合同时，只允许一次私有的 Schema 修正调用；第二次仍不合同则返回 `invalid_model_output`，不无限重试。
- 供应方原始异常和密钥不进入结果；工具输出经控制标签中和后再返回模型。

### Lead 交接合同

- `fact_boundary.allowed_subject_claims` 是唯一可当作主体事实的内容；`do_not_infer` 禁止将 B/C、“或”、源头身份和一般知识补成客户、渠道、现场、素材或能力。
- `coverage_contract` 要求 Lead 报出地图中真实非空的每个轴，防止它又缩成挑选、避坑或供应链。
- `response_contract` 将当前交付缩成根主词、必报轴和一句研究边界。这一轮不同时展开 B/C、平台、形式、承接、计划或追问，完成后立即停止。
- 这是注意力范围合同，不是评分门或业务阶段机。Lead 仍是唯一最终判断者。

## 没有采用的方案

- 不建内容世界向量知识库。当前失败是语义组织和注意力收敛，不是模型缺少“水果有哪些品种”的常识。未来的历史、平台与市场事实需要可引用的研究证据，但它不应拥有定位判断权。
- 不用关键词规则决定主词。确定性代码只校验来源、反事实和结构一致性；完整对象、中间实现物与专业任务的比较仍由有界语义合同完成，无法用行业词表覆盖。
- 不恢复 R7-R14 内容世界选择器，不引入评分门、固定阶段或专家子 Agent 投票。
- 不把成功案例作为隐藏 few-shot 硬编进提示。黄金、海鲜和水果只在评测集和审计证据中，生产探索提示不包含这些答案词。

## 残余风险与下一步

- 模型仍可能在代表性方向中带出未实时核验的具体事实。生产提示已要求去名化为研究问题，但还没有一个通用的命名实体确定性检测器；进入选题和发布前仍必须用浏览器/证据工具核验。
- 一次完整调用需要 Lead 调度、两次有界分析和 Lead 最终收敛，延迟高于普通聊天。Web 聊天使用 SSE 心跳；非流式 Nginx `/runs/wait` 测试在 60 秒返回 504 不代表浏览器 SSE 失效。
- 工业案例中“文化与生活习惯”轴只有环保/处置习惯连接，价值低于消费品案例。地图允许无真实连接时为空，后续评测不应为形式完整强行凑轴。
- 下一个主线不是继续扩写内容世界提示，而是在当前通过的世界边界上，用真实主体信息验证定位、表现形式和商业承接如何继续长出，且不得把内容世界反向压窄。
