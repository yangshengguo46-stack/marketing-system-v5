# 主体回答来源与版本链离线证据

日期：2026-08-11

## 结论

本轮完成了主体回答的离线来源合同：Lead 可将当前运行中结构化 `ask_clarification` 的用户原文追加为 Owner 隔离的 `ProjectTruth`，同一语义问题的后续回答形成替代链。没有发起真实模型调用，M01 仍为 `business-rejected`。

## 失败先行

1. 首个测试因 `incubation_subject_answer_tool` 不存在而失败。
2. 基础实现后，跨线程复用 request ID 错误地被视为同一来源，且项目上下文没有投影 `supersedes_truth_id`；两个测试先红后修复。
3. 子 Agent 最初仍能直接调用写工具；增加运行时拒绝测试后修复。
4. Lead 合同和评测工具面最初没有区分读取与写入；增加失败测试后，记录工具只进入 Lead 工具面。
5. 内置与自定义子 Agent 默认工具限制最初未包含该写工具；增加失败测试后修复。
6. A38 与产品合同测试先因文档不存在而失败，本证据与审计随后补齐。
7. 非交互 Lead 最初仍能看到回答记录工具；新增失败测试后，与 `ask_clarification` 一并从定时任务工具面移除。

## 离线合同

- 工具 Schema：模型只传 `project_id` 与 `fact_key`。
- 身份来源：当前认证运行时。
- 内容来源：当前 run 中相同 request ID 的原始问题与用户回答。
- 来源标识：由 thread ID、request ID 和语义键生成，不暴露原始身份。
- 保存类型：`ProjectTruth.USER_FACT`。
- 修订：新事实的 `supersedes_truth_id` 指向同一语义键的当前事实头。
- 幂等：同一来源重复提交返回 `unchanged`。
- 失败方式：无持久库、无当前 run 回执、错误项目或审批类请求均拒绝或显式不可用。
- 权限：交互式 Lead 可写；所有子 Agent 在配置和运行时均不可写，非交互运行不暴露该工具。

## 验证范围

聚焦测试覆盖来源配对、Owner 隔离、幂等、版本链、项目投影、审批排除、持久化失败和子 Agent 权限。完整测试数量以 `current/EXECUTION_LEDGER.md` 的最终验证记录为准。

本轮没有验证真实模型是否会主动提出高信息问题，也没有验证收到新回答后能否产生更好的孵化修订。这两项必须在新的、经用户明确确认的付费连续会话中验收，不能由离线工具测试推导。
