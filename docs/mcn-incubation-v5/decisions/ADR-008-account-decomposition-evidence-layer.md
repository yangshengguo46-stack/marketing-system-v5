# ADR-008 账号拆解作为孵化证据层

## 背景

对标账号和代表作品能够补充受众情境、平台表达、证明方式和转化观察，但 MediaKit 只覆盖单条媒体的部分原子能力。把账号拆解做成另一个营销 Agent，会与第五版唯一 Lead Agent 的孵化判断权冲突；把一条爆款的结构直接升为规则，又会复制第四版的硬门问题。

## 提议

新增一个下游、只读、可恢复的账号证据能力。它内部编排账号级可见浏览器、MediaKit 和确定性聚合，对 Lead Agent 只暴露一个领域入口和结构化证据结果。

该能力保存规范账号身份、透明样本框、作品观察、媒体原子、模式假设、反例、覆盖率和迁移条件。所有解释都保持为可修订假设；它不选择当前项目定位、不打爆款分、不强制内容模板，也不直接修改孵化决策。

## MediaKit 路由

- 直接复用 `probe-video-metadata`、`asr-subtitles`、`video-ocr` 和 `segment-scenes`。
- 不把只支持短剧/小游戏的高光能力或影视剧情线能力用于通用短视频账号。
- 云端任务必须绑定输入哈希、CLI/Schema 版本、`client_token`、费用和云处理同意、任务回执与输出哈希。
- 用户不同意云处理时，先保留覆盖缺口；PySceneDetect、TransNetV2 或本地 ASR/VLM 只有经 A29 的对照评测证明必要且有效后才采用。

## 数据与授权

浏览器状态按用户、平台和账号隔离，原始会话不返回模型。账号快照和每条作品都保存来源及采集时间；跨时间指标、缺失指标和身份不确定必须显式记录。原始媒体的下载、临时上传和保留分别受权利、隐私、费用与删除策略约束。

账号模式报告通过现有项目证据账本回传，不自动成为 `ProjectTruth`、方法卡或案例记忆。首版使用结构化字段和确定性查询，不引入向量数据库。

## 接受条件

- 10 个版本化失败案例及合同测试通过。
- 一个授权真实账号完成“身份确认 -> 透明采样 -> 媒体原子 -> 模式与反例 -> 项目证据”闭环，人工可逐项复核来源。
- 同名账号、跨地区账号、登录失效和多用户浏览器隔离测试通过。
- 无云处理同意时不会上传媒体；Cookie、LocalStorage、临时链接和密钥不会进入模型、日志或证据结果。
- 账号报告不会把相关性写成因果，不会把单条爆款升为账号规律，不会复制对标表达资产。
- Lead Agent 能使用报告修订孵化建议，同时保留不采用该对标结论的权利。

这些条件满足前保持 `proposed`，不得宣称“输入账号链接即可准确拆出成功公式”。
