# 第五版孵化产品合同

## 命名与独立边界

`mcn-incubation-core` 是内部工作名，产品名称未定。第五版是全新的孵化产品，不以旧 `marketing-os` 为产品名、领域边界或运行依赖。

旧版仓库保持只读。允许吸收经过审计的方法和可靠性经验，但不得迁移固定阶段、营销评分门、语义中间件、强制工具路线或旧数据库真相。

## 产品根定义

第五版的根能力只有一个：**孵化**。

孵化要对一个人、品牌、产品或组织作出持续可修订的经营判断：

```text
真实情况与经营目标
  -> 谁或什么应该成为 IP 主体
  -> 商业对象对应什么品类行为、人类任务与购买情境
  -> 账号可以长期占领什么内容领地并形成商业归因
  -> 由谁、什么场景和什么形式表达
  -> 为哪类人解决什么问题
  -> 凭什么被相信、记住和选择
  -> 内容如何持续产生
  -> 如何承接行为、收入和长期资产
  -> 先做哪个最小实验
  -> 真实结果怎样修正下一版判断
```

内容生产、粉丝画像、对标研究、浏览器、桌面操作、MediaKit、平台发布和数据分析都不是并列大脑。它们只能由孵化决策派生任务，或向孵化内核回传证据。

## 孵化能力树

1. 识别业务目标、主体、资源、能力、产品、权利和限制。
2. 区分 IP 主体与表达载体，不由主体标签直接决定形式。
3. 理解受众问题、欲望和决策情境，不用人口标签替代经营判断。
4. 从专有事实、产品机制、证明和竞争情境形成定位。
5. 从商业对象识别品类中心、修饰关系、品类行为、人类任务、关系张力与购买情境，形成既广阔又能自然回到业务的内容领地。
6. 选择与本人表现、素材、空间、隐私、成本和产能匹配的表达形式。
7. 建立可持续的内容发动机，而不是只给孤立选题。
8. 从付费问题、买方、产品、交付能力和经济约束设计变现。
9. 建立内容到行动、线索、成交、交付、复购或资产积累的连续路径。
10. 用最小实验解决最重要未知，并分别观察内容、受众和商业结果。
11. 保留历史版本、反例和限制，根据结果修订，而不是自动晋升通用规律。

这些是 Agent 可按需使用的判断视角，不是固定工作流。信息不足时，Agent 应给暂定方向、明确未知和下一项最有价值的证据，不能因字段未填满而拒绝继续。

第五版不维护行业模板或“行业 -> 唯一路线”映射。一个项目可以同时具有人物、商品、服务、场所、生产源头和组织等事实镜头；Lead 根据当前目标与证据组合使用。同样叫水果、果农或宝妈的主体，若经营模式、能力、客户、证明和限制不同，内容领地、表现形式与变现判断也必须实质不同。

## 内容世界探索

内容世界探索用于在过早选择定位或表现形式之前打开候选空间。Lead 可以按需组合向上抽象、向下拆分、横向展开和跨维连接：从具体对象进入品类行为与人类任务，拆出可持续的子世界，沿时间、空间、事件、人物与冲突寻找故事节点，或连接现实、历史、神话、影视、游戏和未来世界。它们是可选认知算子，不是固定四步流程、行业关键词路由或必须填满的矩阵。

模型已有知识可以产生创意假设，但不能冒充项目事实或外部证据。涉及历史、文化、作品、产业和当前市场的主张，应通过浏览器或 MCP 核验来源、时间、适用范围与限制；未经核验时保留为推断、假设或未知。

内容世界探索只生成候选，唯一 Lead 仍要根据主体拥有权、持续供给、受众价值、信任形成、商业归因、成本和关键未知做营销取舍。选中节点之后，查理编剧课等叙事方法才负责人物、欲望、行动、事件、阻力、场景与变化等内容加工。叙事方法不拥有定位、表现形式或变现的最终决定权。

项目保存候选、选择、否决原因与修订版本，使模型在后续轮次不再重复已经被用户否决的机械路线；不保存隐藏思维过程，也不把纠偏会话自动晋升为跨用户成功案例。

## 主体信息与连续修订

主体信息不是一次性画像表。Lead 只询问足以反转当前建议的少量未知；它可以在信息不完整时继续给条件化判断，不能把固定问卷、访谈轮数或字段完整度变成起号硬门。

用户通过结构化澄清给出的关键回答，应以**用户原文**和原问题进入 Owner 隔离的项目事实账本。工具只能从当前运行的真实人类回执读取内容，模型不能代填回答、问题或用户身份。同一语义事实的新回答采用追加记录并链接旧记录，形成可追溯的**版本链**；当前上下文读取最新事实，历史版本保留用于解释判断为何改变。

主体事实与**审批**严格分离。发布、付费、版权、账号操作和其他不可逆动作的确认不能写成普通用户事实，也不能因出现在聊天或项目账本中获得执行授权。

## 决策权

只有 DeerFlow Lead Agent 拥有唯一孵化决策权，并对用户可见结果负责。方法卡、案例、受众模型和算法只提供上下文；算法只计算指标、基线、实验差异和异常，不决定人设、定位、内容形式或变现路线。

子 Agent 可以被 Lead 按需调用做有界、只读的研究或证据检查，但它们是执行工具，不是并列大脑。子 Agent 不直接面向用户、不保留独立孵化记忆、不修改项目状态、不审批或执行不可逆操作，也不能再委派。是否调用由 Lead 动态判断，不得恢复固定角色路线、专家投票或评分门。

代码硬约束仅保护所有权、隐私、引用完整性、版本历史、幂等、费用、版权和不可逆动作。

## 首轮范围

- 当前只构建孵化内核、项目事实账本、方法卡、受控案例记忆和架构评测。
- 平台发布、媒体生产、复杂前端和自动跨用户学习不进入本轮。
- 跨项目案例默认不可检索；未来开放必须取得明确授权并完成人工脱敏复核。
- 电影制作类工作流不属于第五版孵化内核。
