# 2026-08-10 模型连接故障证据

状态：根因已确认，首选修复已应用并验证。

## 结论

模型、API Key、火山地址和第五版 Agent 改造均不是故障源。故障由两个当前机器环境条件叠加造成：

1. Wi-Fi 被固定使用 `114.114.114.114`，该 DNS 在当前网络上查询超时；
2. 根目录 `.env` 的 `NO_PROXY` 和 `no_proxy` 都包含火山 `ark`、`amk` 域名，使模型请求绕过本机代理并依赖已经失效的直连 DNS。

只修正代理例外后，同一 `PatchedChatDeepSeek`、同一模型和同一凭证在 2.39 秒内返回 `OK`。这证明供应商、凭证和模型调用链可用。

## 对照证据

- 原第五版日志在 2026-08-06 04:45 至 05:10 多次记录火山 `/chat/completions` 返回 `200 OK`。
- 当前第五版与迁移前原第五版的 `config.yaml` SHA-256 完全相同；第四版的模型名和 API Base 也相同。
- 三个本地 `.env` 中的 `VOLCENGINE_API_KEY` 长度和摘要等价。检查过程未输出凭证值。
- 当前系统解析和 `dig @114.114.114.114` 均失败；路由器 DNS `192.168.0.1` 和三个独立 DNS 均能解析火山域名。
- 将火山域名固定到已解析 IP 后，TLS 请求返回预期的无凭证 `401`；说明公网路由和供应商端点在线。
- 经 `127.0.0.1:7890` 代理访问火山端点同样返回预期 `401`；本地代理在线。
- 普通 Python `httpx` 经代理可达；模型客户端按当前 `.env` 生成了火山域名的直连例外，最终报 `gaierror [Errno 8]`。
- 同时覆盖大小写代理变量，并将大小写 `NO_PROXY` 临时收窄到本机地址后，真实模型流式调用成功返回 `OK`。

## 未证明事项

- 系统配置确认 Wi-Fi 当前持久化了 `114.114.114.114`，但现有日志不足以证明是哪个应用或用户操作最初写入该值。
- TAG 在 22:17 启动并接管 `127.0.0.1:7890` 的系统代理；这能解释当前代理状态，但不能单独证明它写入了 DNS。

## 修复候选

首选是将 Wi-Fi DNS 恢复为 DHCP 自动获取，并保留火山直连。当前路由器 DNS 已验证可解析和直连火山。这是系统级变更，执行前需要明确确认。

备选是在本项目的本地 `.env` 中配置 `HTTP_PROXY`、`HTTPS_PROXY` 及小写等价项，并从大小写 `NO_PROXY` 中移除火山域名。该方案不改变整台电脑，但会让 DeerFlow 和 MediaKit 依赖 TAG 的 `127.0.0.1:7890` 常驻。

## 评测口径

本次 `OK` 仅证明模型传输链可用，不是孵化输出，也不计入 M01、B01、G01 预检或架构竞赛。此前两个未完成运行继续没有 completion，必须排除在质量评估之外。

## 修复结果

经用户确认后，Wi-Fi DNS 已恢复为 DHCP 自动获取，系统解析器使用路由器 `192.168.0.1`。火山域名恢复解析，原始第五版环境中的真实模型在 1.44 秒内返回 `OK`；随后完整 Lead Agent 成功完成三案例预检。网络故障已关闭，孵化输出质量另见 `2026-08-10-preflight-quality-review.md`。
