# ADR-018：采用选题生成与证据桥边界

- 状态：accepted_for_experiment_not_runtime
- 日期：2026-08-14
- 依据：A42、A45、A53、A54、E38、ADR-017、第四版编导因果桥证据

## 决定

第五版明确采用三层边界：语义识别选择并解释内容主语，内容地图只展开冻结根，选题生成从一条地图路径提炼本次中心命题并组织证据。文稿创作是后续能力，不并入选题生成。

下一候选以薄 `TopicBridge` 方法 Skill 开始，按需使用 DeerFlow 现有 `web_search` / `web_fetch`。模型负责关联召回、关系解释和命题收敛；外部来源负责作品情节、人物、历史、原话、数字与当前事实的核验；Lead 保留最终判断权。

本决定不注册新运行时 Tool、子 Agent、中间件或固定工作流，不修改现役核心提示、`analyze_business_semantics` 或 `explore_content_worlds`。Skill、提示和检索形状必须先经过隔离的同模型架构竞赛。

## 原因

`海鲜 -> 牡蛎 -> 《我的叔叔于勒》`证明地图中的关联路径还缺一层“关系为什么成立、这次究竟讲什么”。现有地图刻意只输出待研究连接，不能承担命名事实核验；让写稿模型直接补齐又会重现第四版的事实污染和机械填槽。

模型参数知识适合发散关联与形成解释，但不能提供稳定出处。RAG、Self-RAG、ReAct 与混合检索研究共同支持按任务需要检索，而非每轮固定加载知识。当前命名作品可以通过精确搜索和原文抓取解决，没有证据支持首版引入向量数据库或 GraphRAG 索引。

## 采用的旧版原语

- 从第四版因果桥保留关系/因果边，而不是只做词语共现。
- 保留可选替换检验，判断对象是具体叙事机关还是可替换装饰。
- 保留事实、解释与创意假设分离。
- 从 E31-E34 保留候选召回与最终收敛的诊断区别。
- 从 E37 保留已选根与下游路径的确定性绑定。

第四版的固定人物槽位、强制故事链、生产合同、评分和巨型 Schema 均被拒绝。E29-E37 的失败候选也不得拼接成生产流程。

## 检索规则

- 命名作品、人物、历史、现实事件、数字、原话和高风险事实必须检索或读取用户提供的来源。
- 解释性命题由模型形成，但必须与来源中的可观察事实分开。
- 搜索失败时保留未知或研究问题，不以模型记忆补成确定事实。
- 先精确实体/关键词与原始来源，隐含主题召回才使用语义检索。
- 本地语料规模和重复检索成本达到真实需求后，再通过评测决定是否增加混合索引、向量检索或图检索。

## 非目标

- 不重新选择内容根。
- 不扩写整张内容地图。
- 不决定表现形式。
- 不设计平台、经营、销售或实验。
- 不写完整文稿，除非用户随后明确进入文稿创作。
- 不把语义或叙事关系称为现实市场因果。

## 晋级条件

隔离竞赛必须覆盖模型直答、冻结证据包和按需在线检索三种候选，并由用户案例与未见案例共同验收。通过只能允许一次生产探针，不能自动注册强制阶段。失败候选冻结后停止，不在同一实现上叠规则。

## E38 状态补充

首个海鲜到文学作品的开发探针在一次失败后通过了已知案例的基本人工复核，但仍有解释强度与证据包外标签问题。因此 ADR 状态保持 `accepted_for_experiment_not_runtime`；E38 不构成生产注册或泛化通过的证据。
