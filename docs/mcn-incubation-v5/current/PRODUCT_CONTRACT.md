# 第五版孵化产品合同

## 命名与独立边界

`mcn-incubation-core` 是内部工作名，产品名称未定。第五版是全新的孵化产品，不以旧 `marketing-os` 为产品名、领域边界或运行依赖。

旧版仓库保持只读。允许吸收经过审计的方法和可靠性经验，但不得迁移固定阶段、营销评分门、语义中间件、强制工具路线或旧数据库真相。

## 产品根定义

第五版的根能力只有一个：**孵化**。

孵化要对一个人、品牌、产品或组织作出持续可修订的经营判断：

```text
真实情况与经营目标
  -> 谁或什么应该成为 IP 主体
  -> 由谁、什么场景和什么形式表达
  -> 为哪类人解决什么问题
  -> 凭什么被相信、记住和选择
  -> 内容如何持续产生
  -> 如何承接行为、收入和长期资产
  -> 先做哪个最小实验
  -> 真实结果怎样修正下一版判断
```

内容生产、粉丝画像、对标研究、浏览器、桌面操作、MediaKit、平台发布和数据分析都不是并列大脑。它们只能由孵化决策派生任务，或向孵化内核回传证据。

## 孵化能力树

1. 识别业务目标、主体、资源、能力、产品、权利和限制。
2. 区分 IP 主体与表达载体，不由主体标签直接决定形式。
3. 理解受众问题、欲望和决策情境，不用人口标签替代经营判断。
4. 从专有事实、产品机制、证明和竞争情境形成定位。
5. 选择与本人表现、素材、空间、隐私、成本和产能匹配的表达形式。
6. 建立可持续的内容发动机，而不是只给孤立选题。
7. 从付费问题、买方、产品、交付能力和经济约束设计变现。
8. 建立内容到行动、线索、成交、交付、复购或资产积累的连续路径。
9. 用最小实验解决最重要未知，并分别观察内容、受众和商业结果。
10. 保留历史版本、反例和限制，根据结果修订，而不是自动晋升通用规律。

这些是 Agent 可按需使用的判断视角，不是固定工作流。信息不足时，Agent 应给暂定方向、明确未知和下一项最有价值的证据，不能因字段未填满而拒绝继续。

## 决策权

只有 DeerFlow Lead Agent 拥有唯一孵化决策权，并对用户可见结果负责。方法卡、案例、受众模型和算法只提供上下文；算法只计算指标、基线、实验差异和异常，不决定人设、定位、内容形式或变现路线。

子 Agent 可以被 Lead 按需调用做有界、只读的研究或证据检查，但它们是执行工具，不是并列大脑。子 Agent 不直接面向用户、不保留独立孵化记忆、不修改项目状态、不审批或执行不可逆操作，也不能再委派。是否调用由 Lead 动态判断，不得恢复固定角色路线、专家投票或评分门。

代码硬约束仅保护所有权、隐私、引用完整性、版本历史、幂等、费用、版权和不可逆动作。

## 首轮范围

- 当前只构建孵化内核、项目事实账本、方法卡、受控案例记忆和架构评测。
- 平台发布、媒体生产、复杂前端和自动跨用户学习不进入本轮。
- 跨项目案例默认不可检索；未来开放必须取得明确授权并完成人工脱敏复核。
- 电影制作类工作流不属于第五版孵化内核。
