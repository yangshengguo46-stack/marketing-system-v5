# A23 孵化评测集审计

## 结论

孵化质量不能靠“测试能否调用某个工具”证明。评测必须观察 Agent 是否能把具体业务事实转化为主体、受众问题、表现形式、内容发动机、变现、转化和实验，并在新证据出现时修订。

首版建立 36 个中文业务案例：

| 分组 | 数量 | 代表问题 |
| --- | ---: | --- |
| 宝妈 | 6 | 职业事实、隐私、镜头表现、门店、手艺和服务变现 |
| 专业人士 | 5 | 法律、医疗、建筑、心理和工业专业证据 |
| 职业转型 | 4 | 被裁、退休、副业和旧受众迁移 |
| 本地商家 | 4 | 到店、团队、顾客隐私和同城转化 |
| 消费品牌 | 5 | 品牌载体、信任修复、记忆资产和复购 |
| 单款产品 | 5 | 买方与使用者分离、同质化和产品证明 |
| 服务产品 | 4 | 标准化、团队交付、B2B 线索和续费 |
| 极冷启动 | 3 | 只有意愿、只有品牌名或只有原型 |

每个案例都包含事实 ID、限制、目标、现有产品、关键能力和一条后续新证据。这样可以测量修订能力，而不是只测首轮文案。

确定性检查只覆盖可客观观察的缺口：表现形式和内容发动机是否存在、变现和转化是否连接、是否有首个实验、引用是否来自案例事实、是否说明未知和替代方案、是否承诺爆款或使用刻板标签。

真正的业务质量还需要两个独立模型裁判和 MCN 业务专家校准。裁判评价最终答案，不读取隐藏思考、工具轨迹或固定工作流。评测代码要求五种架构各至少有一个专家校准样本，且对应的机器评分与专家评分绝对偏差不超过 `0.2`，否则状态仍为 `needs_adjudication`。当前案例集没有伪造“黄金成功路线”，专家标注尚未完成。

## 第五版决定

- 将 36 个案例作为版本化测试资产，修改必须评审分布和意图。
- 五个架构候选使用同一模型版本、上下文预算、工具面和案例顺序随机种子。
- 自动规则只查客观错误；定位创意和商业可行性由校准后的裁判评价。
- 不以平均分掩盖高风险失败，需单列编造、刻板印象、隐私和虚假承诺。
- 在真实模型输出和专家校准完成前，不宣布架构胜者。
