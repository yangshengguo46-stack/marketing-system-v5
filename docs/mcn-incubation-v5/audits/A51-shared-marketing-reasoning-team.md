# A51 共享营销推理链团队试验

## 结论

用户把黄金礼品示例进一步蒸馏成一条跨行业营销推理骨架：区分信息采集和营销推演，拆开品类中心与材质或修饰，从名词看动词、从产品看用途、从用途看人性，再把社会行为提升为长期母题，展开内容世界，选择表现形式，并建立不卖而卖的商业归因。这里的关键不是保存一个行业答案，而是让 Agent 对任何商业对象形成一条可解释、可反驳、可修订的完整因果链。

A49 证明把类似思路做成一张方法卡会诱发栏目复写；A50 证明五个专业角色能够真实执行，但泛化的定位、受众、内容、形式和商业化岗位说明没有让五人围绕同一个营销命题工作。本轮因此测试一个更小的修正：五个专家都看见同一套完整因果链，再分别深化语义中心、社会行为与人类需求、内容世界、表现形式和商业归因，最后只由 Lead 总脑收敛成一个统一营销命题。

共享合同不含黄金、礼品、送礼、水果或宝妈等案例答案，不需要向量数据库，也不进入方法卡检索。它是评测专用的紧凑推理约束，不是固定阶段、答题模板、评分器、项目状态或第二运行时。

真实黄金礼品匹配试验已经完成。团队与单 Lead 都技术通过、业务拒绝，没有获胜者。单 Lead 更接近专家锚点，至少选择了“礼品决策参谋”和“重要关系维护”；团队反而收敛到“黄金礼品场景解决方案提供者”、加工实录和避坑内容。两者都没有充分打开送、收、关系与人情世界，也都新增无依据案例、数量或阈值。当前实现不接入生产，生产保持不变。

## 候选结构

五个只读子 Agent 使用 DeerFlow 已有 `task`：

| 子 Agent | 深化板块 | 对完整链条的责任 |
| --- | --- | --- |
| `semantic-center-specialist` | 商业对象中的品类中心、材质或修饰、功能、用途和语义中心 | 比较主语候选，并说明主语变化怎样改变后续内容和生意回路 |
| `human-demand-specialist` | 动作、使用情境、社会行为、人类需求和关系张力 | 审查每次抽象跨越的因果与反例，防止标签推断和远联失控 |
| `content-world-specialist` | 长期母题、人物、事件、关系、冲突、时间、空间和跨领域内容世界 | 检查内容容量与回到商业对象的语义桥，不选择表现形式 |
| `expression-form-specialist` | 口播、对话、情景、纪录、演示、纯素材和图文等表现形式 | 只依据已知主体条件给结论，未知时保留条件化候选 |
| `commercial-attribution-specialist` | 内容、信任、需求心智、行动、产品或服务之间的商业归因 | 检查不卖而卖是否自然，识别只有泛流量没有转化的路线 |

专家不是各自拿一小段流水线。每个系统提示都包含同一套完整因果链，并要求说明本板块会如何改变其他节点。每人只返回候选、因果依据、最强反证、替代解释、关键未知和链条影响；不得面向用户、写状态、提问、再委派、投票或给最终方案。

Lead 同样获得原样合同，在内部维护一条允许留空和推翻的营销论证。收到全部简报后，Lead 必须处理冲突并做取舍，形成一个统一营销命题与自然商业回路；不得直接拼接五份报告，也不得按五个专家分五节复述。

## 对照设计

新增 `reasoning_contract_mode=shared_marketing_chain`。它可以用于：

1. 单 Lead：相同完整合同、禁用宽泛方法上下文、无子 Agent。
2. 推理团队：相同完整合同、同样禁用宽泛方法上下文，加五个只读专家。

因此，同业务合同的单 Lead 是团队因果判断的必要匹配对照。只跑团队可以判断绝对答案是否可用，但不能证明改进来自多 Agent。A50 的 `incubation-team` 保持不可变基线，不能悄悄带上本轮合同后追溯改写历史。

实验清单记录推理模式、合同 SHA-256、系统合同 SHA-256、角色白名单、总委派上限、并发、图步、Token、工具面和实际轨迹。五个角色仍须各恰好执行一次并取得 `task_completed`；这只是隔离实验的操纵变量，不是生产工作流硬门。

## 风险与验收

首要风险是模型再次把内部因果链复写成表格或把抽象词当答案。其次是五个专家虽共享骨架，仍在平行生成同义内容，Lead 只做语言拼接。真实业务复核必须检查：

1. 是否找到比产品属性更有解释力且仍可商业归因的语义中心。
2. 名词、动作、用途、社会行为、人类需求之间是否有可说明的中间因果，而非一句跳跃。
3. 内容世界与表现形式是否真正分开。
4. 产品退出内容中心后，是否仍能自然形成需求心智、信任与行动回路。
5. 是否补造主体资产、客户、渠道、价格、产能、频率、指标或结果。
6. Lead 是否给出一个方案，而不是五份简报的目录。

## 真实匹配结果

| 字段 | 五专家团队 | 单 Lead 对照 |
| --- | --- | --- |
| run | `agent-eval-gold-shared-reasoning-team-v1-20260812` | `agent-eval-gold-shared-reasoning-single-v1-20260812` |
| model | `doubao-seed-2-0-pro-260215` | `doubao-seed-2-0-pro-260215` |
| 方法上下文 | `disabled` | `disabled` |
| 推理合同 SHA-256 | `1b1e392c47e48256147cafc8d9a329c04656e177d92d72366223766579ed115c` | 相同 |
| duration | 135,287 ms | 26,154 ms |
| input / output / total | 47,882 / 1,882 / 49,764 | 30,915 / 908 / 31,823 |
| 技术状态 | 5/5 专家完成，Lead 成功 | Lead 成功 |
| 业务状态 | `business-rejected` | `business-rejected` |

团队答案的核心是“黄金礼品场景解决方案提供者”，内容回到送礼避坑和加工全纪录；它补造加工场景取材条件，提出客户访谈，并给出企业客户 `70%`、3 类各做 2 条、10 天观察等无依据数字。实际委派提示又自行加入“三个候选、优先级排序、至少三个方向”等配额，并让后两名专家读取并未传入它们上下文的“已完成分析结果”。这说明当前协作协议既拆断因果链，又重新生成了第四版式填表压力。

单 Lead 对照提出“礼品决策参谋”，明确连接重要关系维护，因而在这一个匹配样本中单 Lead 更接近专家锚点。但它仍把内容压缩成商务答谢、员工奖励、祝寿等常见场景清单，没有把送与收、人情、礼仪、身份和互惠扩成长期内容世界；又补造企业客户、客户案例、车间等条件化素材，并给出三条测试内容。因此它同样是 `business-rejected`。

这组结果只支持一个有界结论：在相同模型、案例、共享合同和方法关闭条件下，当前“五块并行填充再由 Lead 收敛”没有改善绝对业务质量，而且比单 Lead 更行业化、更昂贵、更慢。它不能证明所有多 Agent 架构都无效，但足以拒绝当前候选，不再通过增加角色修补。

## 第五版决定

1. 保留 A50 及其业务拒绝结果，不原地修改旧团队提示；A51 两个真实输出也保持不可变证据。
2. 共享完整因果链与五个精确营销推理角色只存在于隔离评测配置；当前团队候选被业务拒绝。
3. 不建立知识库或向量数据库；模型参数知识只生成候选，外部事实仍需浏览器或 MCP 证据。
4. Lead 保留唯一最终判断；共享骨架不是固定阶段、完整度门、评分算法或回答模板。
5. 没有获胜者，不接入生产，生产保持不变。下一候选不得继续平行拆分因果链；如继续，应先让 Lead 形成一个完整暂定营销命题，再由少量专家针对同一命题找反证，最后由 Lead 修订，而不是让五人各填一块。
