# ADR-008 语义、内容结构与经营模块分权

- 状态：accepted-boundary / runtime-promotion-deferred
- 日期：2026-08-14
- 范围：第五版孵化核心

## 决定

第五版将业务语义、账号内容结构、表现形式、定位/信任与经营结果视为不同职责。当前只确认前两项的边界：

```text
业务原话
-> 业务语义：用户做的是什么
-> 账号内容结构：来源对象、观众世界、内容发动机、注意力入口
-> 由总控 Agent 在其他独立判断中处理定位、表现形式和经营事项
```

业务语义和账号内容结构不得生成商品方案、广告方案、经营路径或结果指标。内容结构必须解释观众世界与原始业务对象的内容关系，但这不是经营方案。

## 实现规则

- 模型提示使用正向职责和窄 Schema，不靠反复列出模块外词汇提醒模型。
- 不使用“广告、销售、成交”等关键词黑名单；这些词可能是用户合法的业务对象。
- `seller_evidence` 与 `downstream_unknowns` 从内容探索合同退役。生产解析器可为旧模型输出兼容丢弃这两个字段，但不得放宽其他 Schema 字段。
- 账号级候选结构固定为 `source_object`、`audience_world`、`content_engines`、`attention_entries`、`unknowns` 和 `insufficiency`。
- 该候选结构继续离线，不注册为 Tool、Skill、子 Agent 或中间件，直到真实生产探针稳定通过。

## 原因

医美真实账号证明“业务对象”和“观众长期进入的世界”并不总是同一个词；腕表真实账号又证明二者有时确实相同。把内容发动机和注意力入口继续塞进单一内容根，会造成“变美与面部年轻化”这类并列长根，也会把人物钩子误当受众或表现形式。

经营方案混入这两层会转移模型注意力，并诱发不存在的商品、素材、数字和实验。第四版已经证明多处硬门同时控制判断会让模型冲突，因此本 ADR 采用职责分离而不是新的硬门。

## 后果

- 好处：可以准确描述“医美 -> 变美”和“腕表 -> 腕表”两种形状，问题定位也更可观察。
- 代价：现役 `explore_content_worlds` 与四层账号结构暂时并存，不能宣称已经完成生产迁移。
- 风险：模型仍可能发生 Schema 或根一致性漂移；只允许一次 Schema 修复，失败必须返回稳定错误，不能无限重试。
- 后续：至少补充品牌、产品、专业服务和本地门店的真实账号证据，再决定是否替换生产根地图。
