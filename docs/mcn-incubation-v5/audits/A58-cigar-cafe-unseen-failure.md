# A58 雪茄咖未见案例失败

## 盲测设置

- 用户先给出未见业务表达：`我是开雪茄咖的，该怎么起号？`
- Agent 运行时只看到上述原句，没有看到人名、标准答案或判分条件。
- 用户在运行完成前锁定验收路径：`雪茄 -> 与雪茄强关联的历史人物 -> 切/窃格瓦拉 -> 最爱抽哪一款 -> 经典叼雪茄照片中是哪一款`。这里验收的是从人物轴生成可考证的具体选题，人名写法和具体雪茄型号仍需来源核验。
- 新建无记忆线程，模型为 `glm-5-2-260617`，thinking 开启、reasoning effort low，子 Agent 关闭。

## 真实结果

- 运行状态为 `success`，无工具合同错误，总用量 `42,340 tokens`，耗时约 `169.2s`。
- 语义层将商业对象改写为“雪茄与咖啡消费空间服务”，词法主词报为“服务”，最终内容根选为“咖啡馆”。
- 选择理由是“去掉雪茄后咖啡馆世界仍完整”，并把雪茄降成与甜品类似的附加消费品类。
- 地图因此围绕咖啡豆、烘焙、冲煮、空间、咖啡师和常客展开。人物轴没有进入雪茄历史人物，也没有召回切/窃格瓦拉。
- 可见答案还断言“以雪茄为根会过度收窄”，这与用户预先锁定的内容意图直接冲突。

本题按用户锁定验收为 **完整失败**。它不否定四个已知开发案例的 `4/4` 回归，但否定了据此宣称“陌生业务已稳定达到 80 分”。

## 病因

1. **完整性反事实不够。** 当去掉一个词后剩余对象仍有完整世界，不代表该词只是可丢弃的修饰。去掉雪茄后，“雪茄咖”已变成另一个普通品类。当前合同没有单独检查“去词后商业类别身份是否改变”。
2. **地图不是选题。** 现役 `explore_content_worlds` 为了事实边界，首版只输出类别级研究方向，不直接产生未核验的命名人物和历史断言。E38 选题证据桥仍在隔离实验中，未注册到运行时。因此即使上游选对雪茄，当前链路也没有被验证能走到该具体选题。

## 后续边界

- 不把“雪茄”、切/窃格瓦拉或经典照片写进运行时提示。
- 如修正语义层，先建立一组“通用经营容器 + 类别定义对象”的对比题，验证完整性、商业身份和自然回路，不在本题上单点调参。
- 具体人物与物件选题交给下游 TopicBridge：模型负责召回候选，检索负责身份、照片与雪茄型号证据，Lead 负责判断是否成为选题。
