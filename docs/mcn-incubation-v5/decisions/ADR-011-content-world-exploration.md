# ADR-011 内容世界探索候选架构

## 背景

A40-A42 已确认第五版的核心缺口是营销脑，但原有方法卡、来源机制卡、完整 JSON 合同和两遍法都没有通过业务验收。用户在会话 `019ff0ac-ebbf-7520-bae5-2b91f1c4da57` 中进一步演示了模型需要的搜索动作：既能从黄金礼品向上进入送礼与人情世界，又不能把同一路线机械套给水果；还应能从水果向下进入榴莲等子世界，沿时间、空间、事件、人物和冲突横向展开，并连接现实、历史、神话、影视、游戏与未来。

公开课程资料和第四版 Git 证据没有证明这是一套查理课程固定公式。查理方法更适合把选中的世界节点变成人物、欲望、行动、事件、阻力和变化。第五版需要决定的是如何给模型这种认知支架，同时不重演第四版的长提示词、硬阶段、语义中间件和多大脑冲突。

## 候选决定

满足接受条件前，采用以下评测候选，不接生产：

1. 把向上抽象、向下拆分、横向展开和跨维连接定义为**可选认知算子**，不是固定四步流程，也不要求一次全部使用。
2. 用一张短、来源化、版本化的方法卡 `content-world-exploration-v1` 提供算子与反例；Lead 按需读取，不把正文塞进核心提示词。
3. 不以行业或关键词决定算子。关键词/BM25只能帮助发现方法，不能选择内容领地或最终方案。
4. 模型参数知识只用于生成创意假设；涉及历史、作品、文化、产业与当前市场的事实，通过浏览器/MCP即时核验后才进入外部证据。
5. 四向探索先产生少量自然语言候选；唯一 Lead 再按主体事实、可持续供给、受众价值、商业归因、成本和未知作出营销取舍。
6. 取舍完成后才把必要内容映射到现有 `TerritoryCandidate`；不要求模型直接填写完整结构，不新增数据库表或完整度门。
7. 只保存用户可见候选、事实/证据引用、选择、否决原因、未知和修订原因，不保存隐藏推理过程。
8. 查理等编剧方法位于候选探索之后或候选验证期间，负责**叙事加工**；它们不拥有**营销取舍**，也不恢复电影化 IP 产品与电影生产流程。
9. 有界只读 explorer 只作为对照候选；是否调用由 Lead 决定，不能写状态、直接面向用户、递归委派或成为第二运行时。
10. 当前小型方法卡直接读取，不建向量库。未来只有检索与最终业务评测共同证明需要时，才比较 BM25、embedding、混合检索与重排。

## 明确不采用

- 把四种算子和所有行业例子写进 Lead 核心提示词。
- 强制执行“向上 -> 向下 -> 横向 -> 跨维”或填满五维矩阵。
- `if industry == ...`、关键词分类器或语义分数自动选择路线。
- 把模型联想直接写成外部事实或项目事实。
- 为一张短方法卡预建向量数据库、知识图谱或行业本体。
- 把用户纠偏会话提升为真实成功案例或跨用户自动记忆。
- 让查理 Skill、编剧子 Agent、explorer 或结构化输出编译器替代 Lead 决策。

## 分层职责

| 层 | 职责 | 不拥有 |
| --- | --- | --- |
| 内容世界探索 | 扩大候选搜索空间，标明语义桥、世界节点、反例和未知 | 最终定位、表现形式和变现决定 |
| 外部研究 | 核验历史、作品、文化、产业和当前事实 | 将一般知识自动推成项目适配 |
| Lead 营销取舍 | 结合主体、受众、供给、归因、成本与实验选择或暂缓 | 伪造主体事实、结果和数字 |
| 叙事加工 | 把选中节点组织成人物、事件、目标、冲突、场景和表达 | 改写已批准的营销定位 |
| 项目账本 | 保存事实、证据、候选、否决和修订版本 | 用相似度决定事实真伪 |

## 预期影响

- 模型获得明确的发散方向，但仍可根据案例只选一至数个算子。
- 黄金礼品、水果、果农、宝妈、品牌和服务不再共享一条机械语义上升链。
- 充分利用模型已有广泛知识，同时把不可核验联想留在假设层。
- 课程知识、营销判断和执行工艺不再混成同一个 Skill 或提示词。
- 多一次 explorer 调用是否值得，会由跨案例业务结果决定，不由架构偏好决定。

## 2026-08-11 单遍试验更新

Run `content-world-conversation-v1-20260811` 在黄金礼品和水果两个专家纠偏案例上完成 4/4 次真实模型调用，但 conversation-v1 算子版没有比基线更好地打开内容世界，且继续补造资产、订单、数字与产品。**单遍方法卡候选已被拒绝**，不接生产。

A45 随后证明该评测没有线程记忆、Skill、第四版运行时或完整 DeerFlow 母提示词污染。更直接的问题是：评测把完整孵化责任、最终客户交付与内容世界探索混在同一遍，模型在稀疏信息下回到了常见账号模板。这不否定四种认知算子本身，但否定了直接附加到最终回答的用法。

下一评测候选改为 `content_world_exploration` 纯探索模式：基线与 conversation-v2 算子版使用相同原始请求和事实，只生成世界节点、语义桥、反例和待外查主张，不做最终营销取舍。该候选仅存在评测代码中；未获得新的费用授权前不执行真实调用。

## 2026-08-11 用户指令后的最小生产试装

用户随后明确要求“先让 Agent 具备这个思路”，并要求当前先把用户真实情况放到子任务之外，避免再次与完整方案交付打架。A46 因此没有晋升 conversation-v1 或 conversation-v2 评测卡，而是在唯一共享 Lead 契约里重新写入更薄的 `MARKETING_WORLD_THINKING_CONTRACT`：只保留内容世界判断、四种可选视角和定位/内容/表现形式的术语边界，且不含黄金礼品、水果等答案示例。

这是一项用户指示的生产假设，不是 ADR 已接受的证据。A46 当时只证明提示词装配和边界测试通过；评测专用 explorer 是否值得额外模型调用仍按本 ADR 的接受条件另行判断。

## 2026-08-11 生产 Lead 试验更新

A47 在用户明确授权后，用原始黄金礼品与水果请求对现有生产 Lead 做了两个独立 trial。首个 run 因组合线程 ID 超过 64 字符而在模型调用前失败，两个 case 都是 `0 events`、`0 Token`；有界线程 ID 修复经测试后，第二个 run 技术 `2/2` 完成，共使用 64,005 Token。

业务结果仍不通过。黄金答案继续以黄金为语义中心，没有进入礼品、送礼与人情世界，并补造客户故事和订单素材；水果识别生命周期是局部正信号，但仍收窄成三个方向和经营角色模板，也没有真正展开时空、人物、事件、冲突与跨维世界。两例都自主读取 `content-engine-v1` 与 `incubation-model-v1`。这些轨迹支持下一步离线检查方法检索是否重新引入完整孵化压力，但不能证明它是唯一根因，也不能据此强制工具路线。

因此 ADR 继续保持 `proposed`。未经新的用户确认，不发起下一轮付费调用。

## 2026-08-11 方法上下文消融更新

A48 获得用户授权后，保持模型、系统合同、语料、任务模式、记忆和子 Agent 设置不变，只在评测工具面移除 `incubation_context`。消融组技术 `2/2` 完成，共 59,967 Token。黄金首次明确“黄金只是载体”并触及“送什么礼”，水果首次稳定进入历史、流行文化和未来世界；宽泛方法上下文因此从待验证推断升级为有对照支持的重要干扰源。

消融组仍未通过业务评审：黄金继续收缩成三类账号方向并补造供给，水果继续出现三块模板、健康/价格主张和任意数字。这说明方法上下文不是唯一病根，也不支持全局删除生产方法。ADR 继续保持 `proposed`；下一候选应比较紧凑的任务相关方法投影与母合同边界修正，而不是生产关键词路由、强制工具路线或无方法常态。

## 接受条件

- 指定纠偏会话、黄金礼品锚点、水果对照，以及新增个人、品牌、单品、服务和组织锚点完成人工评分。
- 相同模型与上下文预算下，短方法卡在候选差异、语义桥、主体适配、商业归因、反例和事实边界上稳定优于薄基线。
- 强制四步对照没有被误认为目标架构；若它意外胜出，也必须检查是否形成新的语义硬门。
- 若只读 explorer 被采用，其业务增益必须覆盖额外成本和延迟，且 Lead 能删除其无依据主张。
- 至少个人、品牌/门店和产品各完成一个真实“探索 -> 取舍 -> 内容实验 -> 结果 -> 修订”闭环。
- 生产改动仍只有一个 Lead 决策权，不增加行业路由、固定阶段、语义评分拒绝、强制工具路线或第二运行时。

## 与 ADR-010 的关系

ADR-010 定义跨行业营销脑的总体候选和 `TerritoryCandidate` 保存边界；本 ADR 细化“候选怎样被打开、怎样核验、怎样与叙事加工分开”。它不取代 ADR-010，也不改变 A42 的业务拒绝结论。

条件满足前保持 `proposed`。A43-A45 的评测卡与 explorer 仍不得注册到生产方法库、`incubation_context` 或 Lead 提示词；A46 的新极薄契约只作为用户指定的生产试装。A47-A48 已证明当前生产组合与无方法消融都未通过黄金礼品和水果业务验收，任何一方都不能被写成架构胜者。
