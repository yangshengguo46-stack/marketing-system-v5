## 现役原则

Lead 是唯一面向用户作出孵化判断的总脑。核心提示只保留营销推演、内容世界、定位/内容/表现形式边界、商业归因、事实边界和必要审批；不预置行业答案，不强迫完整方案，不强迫实验，不设置阶段、评分、数量或候选配额。

任何新提示候选都先在独立分支或标签验证。失败候选冻结，不叠加到现役提示；通过人工业务复核后，才能用一个替换提交进入现役分支。

## E01 受控协作架构对照（预登记）

- 目标：检查“项目事实简报 + 并行有界顾问 + Lead 收敛”是否比单 Lead 稳定产生更好的孵化判断。
- 固定模型：`glm-5-2-260617`，开启 thinking；新会话，关闭记忆、Skills、外部工具和子 Agent 递归。
- 固定问题：“我是一个做黄金礼品加工的，你有什么起号建议？”
- 共享事实简报：唯一已知事实是“用户自述从事黄金礼品加工”；其他主体、客户、资源、渠道、履约和表现能力均未确认。
- A 组：现役核心提示 + 共享事实简报，由单 Lead 直接回答。
- B 组：语义与需求、内容世界、反方与商业连接三个并行顾问只返回建议与未知，不制定最终方案；现役 Lead 读取三份结果后独立取舍并回答。
- 人工复核维度：语义主语与长期需求、内容世界容量、回到生意的逻辑、事实与未知边界、内容/素材/表现形式区分、是否回退到 B/C 或其他通用模板。
- 拒绝条件：如果 B 组只是更长、带来更多假设、让顾问取代 Lead 决策、形成固定流程，或不能明显改善最终业务判断，则不采用。

## E01 受控协作架构对照（结果）

- A 组单 Lead：约 `51.57s`，`4,419 tokens`。答案正确找到“黄金是材质、礼品是用途、人情与人生节点是内容母题”，将加工能力放在信任证明位置，并建立“懂送礼 → 触发需求 → 承接定制”的商业连接。残差是仍提出 B/C 分叉，并略微默认个人专家人设。
- B 组三顾问加 Lead：顾问分别使用 `2,464 / 3,427 / 2,596 tokens`，Lead 收敛使用 `9,347 tokens`，整条路径约 `17,834 tokens`、约 `159s`。最终答案没有产生新的关键洞察，却增加了“必须私域承接”、物流安全、水贝、订单能力、错误客群和加工素材等未确认事实或分支。
- 内容世界顾问越过职责边界，自行选择表现形式并补造可用素材；反方顾问把风险假设写成经营事实；Lead 又大段吸收这些建议。并行角色没有形成有效制衡，反而把各自的模板惯性汇总到最终答案。
- 结论：A 组胜出，E01 B 组拒绝。第五版不采用固定“三顾问会诊”阵容，不把一次回答变成必须经过多角色的流水线。

## E02 只读审计协作对照（预登记）

- 目标：验证子 Agent 不参与出方案、只审计 Lead 草稿时，能否减少事实越界和模板回退，同时保持 Lead 唯一决策权。
- 固定模型：`glm-5-2-260617`，开启 thinking；关闭记忆、Skills、外部工具和子 Agent 递归。
- 固定输入：沿用 E01 的问题、事实简报和 A 组原始草稿，避免重新采样造成无关差异。
- 审计员只允许指出草稿中的无依据事实、语义主语回退、内容母题与证明素材/表现形式混淆、默认人设或形式、无必要业务模板分叉，以及是否回答了当前问题；禁止提出新定位、新方案、新内容方向或重写答案。
- 最终 Lead 同时读取原问题、事实简报、原草稿和非约束性审计意见，自行核验，只做确有必要的修改。审计意见没有裁决权，Lead 可以拒绝错误意见。
- 人工复核沿用 E01 六个维度，并额外比较信息密度、字数、延迟和 token 成本。
- 通过条件：最终答案保留原草稿的营销洞察，明显减少越界或模板分叉，且没有新增事实、方向、角色或固定步骤。
- 拒绝条件：最终答案只是换写或变长，审计员变相提供方案，Lead 机械接受审计，新增未经确认内容，或改善不足以抵偿额外成本，则不采用常驻审计协作。

## E02 只读审计协作对照（结果）

- 审计调用：约 `48.22s`，`2,981 tokens`；复核调用：约 `24.34s`，`4,853 tokens`。协作路径合计约 `72.56s / 7,834 tokens`，高于 E01 单 Lead 的 `51.57s / 4,419 tokens`。
- 审计员准确指出原草稿末尾的 B/C 分叉和身份分叉不是回答当前问题所必需；最终 Lead 删除两段，保留“礼品/人情是内容母题、加工能力是信任证明、内容如何回到成交”的核心判断，未新增方案或事实，答案明显缩短。
- 审计员漏掉“中国人送黄金从来……”等未经外部证据支持的泛化，也没有质疑“懂黄金礼物的人”是否过早固化主体人设；它把条件化提问本身近似判成事实越界，审计精度仍有限。
- Lead 的最终修改几乎逐项执行审计员的删除建议，没有表现出足够可观察的独立否决。E02 证明只读审计比平行出方案更有价值，但单例结果不足以支持每轮常驻，其延迟和 token 增量也需要由稳定收益证明。

## E03 只读审计迁移验证（预登记）

- 目标：确认 E02 的改善不是黄金礼品案例特例，并检查审计是否会误删必要的条件化判断。
- 固定模型与隔离条件同 E02。每个案例先由现役 Lead 独立生成 A 组草稿，再由同一只读审计协议检查，最后由 Lead 复核形成 B 组；A 草稿同时是 B 组唯一初稿。
- 水果店案例：“我是一个开水果店的，有什么起号建议？”唯一已知事实是用户自述开水果店。门店位置、客群、货源、仓库、配送、团购、案例、素材、履约和表现能力均未知。
- 宝妈案例：“我是一个宝妈，想做账号，你有什么起号建议？”唯一已知事实是用户自述为宝妈并想做账号。经历、能力、产品、职业、目标受众、资源、隐私边界、变现目标和表现能力均未知。
- 水果店复核重点：是否从商品名进入购买/食用/关系需求，是否把门店日常或进货素材误当母题，是否虚构配送、团购、仓库或默认真人出镜。
- 宝妈复核重点：是否识别“宝妈只是身份，不自动等于定位”，是否套用育儿、家庭或口播模板，是否在关键信息不足时提出真正能反转方向的聚焦问题。
- 通过条件：B 组在两个案例中都比 A 组减少实质越界或模板回退，同时保留必要的条件化判断；审计员不得提出替代方案，Lead 不得机械接受错误意见。
- 拒绝条件：任一案例只是变短、增加新事实或分支、被审计员改写策略、误删必要判断，或提升不稳定，则不把审计设为固定运行步骤。

## E03 只读审计迁移验证（结果）

### 水果店

- A 组单 Lead：约 `71.59s / 4,802 tokens`。答案未虚构仓库、配送或团购，但把定位直接定为“最懂水果的那个人”，默认个人专家人设；内容退回选果、时令、品质判断三类行业知识，没有充分进入水果服务的生活关系与长期需求；末尾一次提出门店形态和出镜能力两个问题。
- 审计加复核：额外约 `104.17s / 8,502 tokens`。审计员错误地把“最懂水果的那个人”判为正确推进，也没有发现三分法断言、默认人设、内容世界容量不足和多问题澄清，只修正了“产品不是主角”一句的歧义。B 组几乎原样保留 A 组，未产生实质提升。

### 宝妈

- A 组单 Lead：约 `36.66s / 3,903 tokens`。正确识别“宝妈身份不自动等于定位”，但仍列出带自己的货、带别人的货、广告、纯分享等常见变现模板，并用辅食、早教、收纳、亲子关系和若干家庭活动举例，形成身份刻板推断。
- 审计加复核：额外约 `171.68s / 12,299 tokens`，其中审计单次约 `144.70s / 7,396 tokens`。审计员准确指出传统宝妈赛道和生活画面的预设，B 组删除了这些例子；但仍保留预设变现分叉、一次捆绑多个问题，并新增“很多新号起不来”等无证据泛化。改善存在但成本过高且不完整。

### 决定

- E03 按预登记标准不通过。只读审计在黄金和宝妈题上能做局部删减，在水果店题上却漏掉核心问题，收益不稳定；不能成为每轮固定步骤，也不能成为 Lead 输出前的硬门。
- E01 与 E03 共同排除两种固定阵容：多个顾问共同出方案会汇总模板和臆测；固定审计员会增加延迟、token 和新的误判来源。第五版不新增这两类常驻子 Agent。
- 多 Agent 能力仍保留在 DeerFlow 原生运行时，但只在具体任务出现真实隔离收益时按需使用，例如独立采集外部证据、读取账号数据、核验事实或处理媒体；子 Agent 不负责填充一套固定孵化表，也不参与投票决定定位。
- 当前最小实现保持不变：单 Lead 直接回答是默认路径。下一阶段优先扩充未见业务评测并定位“为什么通用语义原则在黄金题生效、在水果店题退回行业知识”，在证据出现前不继续堆提示、方法卡、知识库或工作流。

## E04 近端答案停止原因诊断（预登记）

- 目标：判断水果店退回“挑选/时令/品质知识”，是否因为现役提示允许模型把第一个合理的行业专业答案误当成长期内容母题。
- 固定模型：`glm-5-2-260617`，开启 thinking；新会话，关闭记忆、Skills、工具、MCP 和子 Agent。三个候选除一条通用思考原则外完全相同。
- A 组：现役核心提示，不增加原则。
- B 组“近端答案检查”：不要把“更懂产品、教人挑选、避坑、科普行业知识”自动视为定位；如果答案仍只是购买或使用产品的近端帮助，则继续寻找用户反复面对的任务、处境、关系、风险或结果。只有新母题更能解释持续关注理由且能自然回到生意时才采用，远离产品本身不是目标。
- C 组“非购买关注检查”：确定母题前检查，即使受众此刻不购买该产品，所讨论的任务、处境、冲突或结果是否仍值得持续关注；如果内容只能在交易附近成立，通常只是销售选题而非内容世界。该检查不得把专业服务或工业业务强行改写成生活情绪题。
- 固定案例：水果店；工业润滑油；企业财税服务；只有“宝妈、想做账号”这一身份信息的个人主体。每题唯一已知事实就是用户原句，其余客户、资源、能力、产品结构、渠道、素材、表现和变现目标均未知。

## E13 任务级认知聚焦架构（研究结论与预登记）

### 术语与能力边界

- “注意力转移”在本项目中指**任务级认知聚焦**：通过选择高信号上下文、任务特定思考视角和纠错对照，提高模型在生成时关注正确问题的概率。它不是直接设置 Transformer 的 attention weight；当前托管模型 API 只能通过输入上下文、工具和采样配置间接影响生成。
- “按照我们的预设”只能预设**认知视角、事实边界和判断目标**，不能预设行业答案、固定路线或必填结构，否则只是把第四版的硬门换成隐性提示门。

### 外部研究对照

- Anthropic 将 Agent 上下文工程定义为每次推理时筛选最佳 token 集，并指出模型存在有限的“attention budget”和长上下文衰减；因此首要机制不是加更多知识，而是在每个任务中只给最小高信号材料。
- SELF-DISCOVER 的核心不是一条通用思维链，而是让模型从原子推理模块中 `SELECT → ADAPT → IMPLEMENT`，为当前任务组成专属推理结构。这比“每题都向上抽象”或“每题都跑四个方向”更符合本项目。
- Directional Stimulus Prompting 证明了黑盒模型可由一个实例级的短提示线索引导，不需要直接修改大模型。它支持“先产生当前任务的聚焦提示，再由 Lead 回答”这个候选，但论文采用了可训练的小策略模型，不能直接当成当前营销任务已经验证。
- System 2 Attention 使模型先重写出只包含相关信息的上下文，再生成最终答案；Step-Back Prompting 先提取更高层概念和原理。它们分别可作为“清理无关上下文”和“向上抽象”的候选镜头，但都不应成为每题必走流程。
- 对比推理研究支持通过正确/错误及其差异引导判断，与 E12 “正例 + 反例 + 机械迁移为什么错”的局部正信号一致；但现有研究任务不是 MCN 孵化，仍必须以本地评测为准。
- Agent Skills 的渐进加载将名称与描述作为常驻索引，只在匹配任务时读取完整 `SKILL.md` 和所需资源。DeerFlow 已有对等机制：延迟模式只注入 Skill 名称，Lead 可经 `describe_skill` 获取元数据后再用 `read_file` 读取正文；因此不需要为本能力新建向量库或第二个 Skill 运行时。
- Anthropic 的 Agent 工程建议是先用简单、可组合的方式，只在评测明确改善结果时增加工作流程或多 Agent 复杂度。

### 本地证据与病根

- E10/E11 已证明：把“四个方向”或“先比较上下尺度”写成静态软指令，模型仍会回到行业起号模板。这不是上下文不够长，而是缺少实例级的视角选择。
- E12 证明纠错对照能改变耳塞题的语义尺度，但在花店题中又机械模仿向上抽象。因此对比案例只能是备选材料，必须由当前任务先选视角，不能固定常驻。
- 归档 A42 的两遍法曾局部改善黄金礼品，但中间输出生成了工厂、订单、素材和数字等新假设；完整 JSON 合同还会迫使模型补齐字段。所以新候选不能让第一遍交付营销方案，也不能使用必填 JSON。
- 固定多顾问与常驻审计员已在 E01-E03 失败：它们放大模板、假设、Token 和延迟，并没有稳定改善语义主语。多 Agent 不是注意力转移的默认解法。

### 首选候选：动态聚焦帧

- 保持现役薄核心不变：它只管 Lead 身份、营销目标、事实边界、回答当前问题和不可逆操作。不再往核心追加行业知识、示例或新步骤。
- 建立一个评测专用的“营销语义重构” Skill 候选。它只在起号、定位、内容世界或营销主语判断时可见，只保存原子视角、纠错对照和事实纪律，不保存行业答案、平台规则、数量、阶段或最终输出模板。
- Skill 不直接给方案，只帮同一个 Lead 为当前任务形成一份短的私有“聚焦帧”：当前真正要回答什么；哪些是已知与未知；最容易滑入哪种熟悉模板；本题值得比较哪些语义主语或尺度；哪个反向视角可防止机械迁移；什么新信息才会反转当前判断。项目可缺失，不做完整度校验，不作为用户可见答题表格，不进入业务真相源。
- 原子视角只是候选：对象的材质/修饰/用途/动作/关系；保留当前大类；向上抽象；向下拆子世界；按时间、空间、人物、事件和冲突横展；跨现实、历史、文化或未来连接；主体拥有权；内容到生意的归因。Lead 只选当前有用的少数视角，不得全部执行。
- 第一候选先使用 DeerFlow 现有渐进 Skill 加载和模型本身的 thinking，不新建中间件或子 Agent。只有这个单调用候选仍不能稳定选择视角时，才隔离测试“同模型先生成非约束性聚焦帧，再由 Lead 回答”的两次推理候选。这个两次候选不允许第一次产生营销方案、业务事实、内容选题、数字或最终决定；Lead 可以全部拒绝。
- 知识库不是首选。RAG 可以召回事实、方法或历史案例，但不保证模型选对语义尺度；只按相似度召回黄金礼品，还可能重现花店的“全部向上抽象”。未来案例检索必须同时召回支持例、反例、适用条件和失效原因。
- 多 Agent 只在采集市场证据、读取账号数据、验证外部事实或独立媒体处理时按需委派；不把语义尺度分给多个顾问投票。Lead 仍是唯一孵化决策者。
- 当已积累足够多样、已审核的用户纠错时，可将“用户输入 → 可观察聚焦帧 → 最终判断”与失败对照做 SFT/偏好优化，把这种选视角的习惯蒸馏进模型或小策略模型。不保存或要求模型暴露隐藏思维链，只训练可观察的判断产物。

### 架构竞赛

- A 组：现役薄核心，单 Lead 直答。
- B 组：现役核心 + 渐进加载的原子视角 Skill，单次模型调用。
- C 组：B 组 + 实例级私有聚焦帧，先在评测器中使用同一模型的两次推理，不接生产工具或状态。
- D 组：C 组 + 按当前任务召回一组支持/反例纠错对照。只有 C 组先稳定改善时才运行 D 组，避免将案例过拟合与聚焦机制混在一起。
- 首批留出类型至少覆盖：窄单品、宽品类、专业近端需求、身份信息不足、品牌与服务；黄金礼品只作校准锚点，不作唯一验收题。
- 评测最终业务判断，不要求固定内部轨迹。聚焦帧只作排障证据；核心维度是语义主语与尺度、内容世界容量、回到生意的因果、事实纪律、内容/证明素材/表现形式区分、是否模板化以及是否回答当前问题。
- 任一候选只是变长、结构更整齐、返回更多方向，或引入新的事实发明、示例词义泄漏、固定步骤与输出表格，均不得晋级。只有业务结果稳定改善才能修改生产提示、注册 Skill 或实现聚焦工具。

## E13 任务级认知聚焦架构（结果）

### 实验完整性

- 实验在隔离分支 `codex/e13-cognitive-focus` 上完成，没有修改现役 Lead 提示、模型配置、Skill 注册、记忆、工具、MCP、子 Agent 或业务状态。评测器直接调用配置中的 `glm-5-2-260617` 思考模式，三组共 `20` 次模型调用全部技术成功。
- 五个用例为黄金礼品加工、花店、水果店、工业设备防护包装和仅有宝妈身份的个人主体，分别覆盖窄组合对象、宽品类、专业近端需求和身份信息不足。各组用户原题、现役完整 Lead 提示、provider 采样和输出上限一致，执行顺序使用固定种子随机化。
- 评测脚本用 `11` 个新测试锁定任务通用性、非全镜头执行、用户原题不变、真实输入边界、聚焦帧标签转义、A/B/C 调用次数、隐藏思考字段不持久化、精确调用上限和原子结果写入；与现役提示测试合计 `42 passed`。
- 本地原始结果保存在 Git 忽略的 `.deer-flow/cognitive-focus-eval/e13-ab-glm-20260812-v1` 和 `e13-c-glm-20260812-v1`，只含可见答案、聚焦帧、哈希、用量和完成回执，不保存密钥或 provider `reasoning_content`。

### A 组：现役薄核心

- 五题共 `18,909 Token / 224.69s` 累计生成时间。它仍有既有残差：花店被直接定为懂花也懂人，水果停在懂水果/帮避坑，工业包装补入设备金额和运输场景，宝妈回到变现与资源模板。
- 黄金礼品仍是 A 组最强项：正确将礼品/送礼作为主语，将加工作为信任证明；但末尾仍退回 B/C 客户和工厂/门店分叉。

### B 组：单次原子视角 Skill

- 五题共 `19,909 Token / 230.41s`，比 A 多 `1,000 Token`，没有产生跨类型稳定改善。
- 花店把“花不是花，而是关系”直接定为唯一核心，忽略花卉品种、种植、地理、历史、艺术与不同经营模式，重复 E12 的向上抽象过拟合；还把“日常订单里每天都有故事”当成主体既有素材。
- 水果店仍是专业选品、社区店老板和产地/供应链三条熟悉模板，又一次把“有没有产地故事”当作唯一聚焦问题；没有将宽品类展开为子世界。
- 工业包装正确进入安全抵达与运输风险，但补造了几十万/上百万设备、设备厂的决策职位、行业失败案例和可拍现场；宝妈虽识别身份不等于定位，又用四类变现路径、职业举例和“月销几十万”的虚构对比填满回答。
- 黄金礼品保留正确语义拆解，但比 A 更早启动婚嫁、企业和个人定制的业务分叉，没有产生新的内容世界深度。
- 结论：静态原子视角被 GLM 理解成一组要执行的方法，没有学会针对任务选视角。B 组不进生产 Skill。

### C 组：同模型动态聚焦帧

- 五题共 `28,617 Token / 324.07s`，相比 A 多约 `51% Token` 和 `44%` 累计生成时间，仍没有产生稳定业务增益。
- 聚焦帧本身就会将模型行业先验提升为后续上下文：花店先预设了同城引流/配送/审美三目标，水果先预设社区店与产地直发二分，黄金先预设 B 端代工与 C 端定制，工业包装先预设低频 B 端与特定产业链角色。它们并非用户事实，却获得了类似“已完成分析”的权威感。
- 第二遍 Lead 大量吸收了这些假设。花店回答变成同城、配送与审美三路径；水果直接进入社区实体店与全国发货二选一，并补出 `1-3 公里`半径；宝妈虽保留“身份不是主语”，仍绑定技能/兴趣与母亲/家庭关系两路径并一次询问两类事实。
- 黄金礼品出现明显回归：C 组开头将“加工过程本身”定为核心内容资产，补入熔金、倒模、修蜡、古法金和錆刻等未确认工艺，再回到 B/C 漏斗。它不仅未改善黄金锚点，还破坏了 A/B 已稳定守住的“加工是证明而非主语”。
- 工业包装的语义主题仍较合理，但继续补出百万设备、运输损坏、项目工期和产线交付等未核验内容，不能抵消其他类型的失败。
- 结论：“先让同一模型选注意力方向，再让它回答”不等于增加了营销智能；当第一遍的视角选择能力本身不足时，两遍法只会将同一个先验错误绑定到上下文后再放大。C 组不进生产工作流程。

### 决定与新边界

- E13 A/B/C 架构竞赛不通过。按预登记不运行 D 组，不建案例检索、向量库或正反例自动路由；它们无法修复视角选择器本身的判断缺陷，反而可能放大 E12 的示例过拟合。
- 不在现役核心追加新规则，不注册“营销语义重构” Skill，不实现聚焦中间件，不增加语义顾问子 Agent。现役 `main` 保持 A 组直答。
- 本轮推翻的不是“上下文能影响注意力”，而是“只要多一遍选视角就会选对”。上下文确实强烈影响了第二遍，但影响方向由第一遍的质量决定。
- 下一研究问题改为：**怎样获得一个比当前 GLM 更可靠的视角选择信号**。可验证的顺序只保留三类：更强底模对同一聚焦任务的迁移；经人工审核且够多样的“输入 → 聚焦产物 → 反例”数据用于 SFT/偏好优化；或一个经标注与离线奖励训练的小策略模型。三者都必须先证明自己能在花店、水果、专业工业品和身份不足类型中选对视角，才能进入 Lead 上下文。
- 当前用户专家纠错数据仍过少，不足以启动微调或小策略模型训练。下一步优先把会话中的真实纠错整理成多行业可观察标注，而不是继续改 Prompt。

## E14 视角选择数据来源与抖音采集边界

### 问题纠偏

- E13 缺的不是一批“播放量高的视频”，而是能监督视角选择的业务标注：同一组已知事实下，模型关注错了什么、为什么错、应该比较哪些主语、最终选中什么、什么新事实会推翻该选择。
- 抖音账号与作品只能提供观察证据，例如账号公开自述、作品主题、表现形式、发布时间和公开互动计数。它不能直接证明创作者当初为什么这样定位，也不能证明高互动来自定位、选题、投流、既有粉丝、名人效应、发布时间或其他变量。
- 因此平台观察数据与专家纠错数据必须是两套数据集。前者可支持市场研究、账号拆解和结果复盘；后者才可能用于视角选择器的监督评测、SFT 或偏好优化。禁止用“高播放 = 正确营销判断”自动生成训练标签。

### 拒绝批量抖音爬虫

- 2026-08-12 核对的[“抖音”用户服务协议](https://www.douyin.com/agreements/?id=6773906068725565448)第 5.1 条明确限制使用自动化程序、软件或类似工具接入抖音并收集或处理其中的信息与内容。第五版不得以批量公开账号爬虫、私有接口逆向、验证码绕过、反检测浏览器或 Cookie 提取建立数据集。
- 本轮曾建立空实验分支 `codex/e14-douyin-public-observer` 评估实现位置；在写入任何代码、数据或配置前发现上述边界，随后删除该分支。现役 Lead、提示词、Skill、浏览器配置和运行时均未改变。
- 第四版的账号浏览器采集实现仍只作为失败案例审计证据。其来源追踪、页面哈希、采样覆盖、字段缺失、渲染文字限定和不读取浏览器存储等可靠性语义值得保留，但不能据此绕过平台对自动化采集本身的限制，也不得整包迁移旧 Personal-IP 运行时。

### 可采用的数据来源

- **用户与 MCN 专家的真实纠错**：把实际问答中的错误答案、逐句纠偏、修正后的可观察判断和适用边界整理为金标。这是当前最稀缺、也最接近护城河的数据。
- **经许可的专家案例**：与 MCN 操盘手共同复盘真实项目，或使用拥有训练和衍生权的内部课程、咨询记录与项目复盘。每条必须记录授权范围、来源、审核者和可用状态。
- **账号本人授权的第一方数据**：抖音开放平台提供经用户授权、经权限申请的视频与账号统计数据能力，适合未来回收自有或客户账号的真实结果，不适合抓取任意竞品。[视频数据接入方案](https://open.douyin.com/platform/resource/docs/ability/open-data/video-data-solution)、[权限说明](https://open.douyin.com/platform/resource/docs/accession-guide/type-and-permission)
- **用户主动提供的材料**：允许用户上传自己有权使用的创作者中心导出、截图、作品链接、脚本、评论摘要和成交记录；系统保留来源与同意，不自动扩展到该账号的其他内容。
- **人工、小样本的公开研究**：研究员可按平台正常使用方式观察并引用少量公开页面，记录 URL、日期与局限，用于形成待审核假设；不得自动批量化，也不得直接升格为训练金标。
- 合成案例只能扩充评测覆盖，不能自我产生正确标签。必须由用户或合格专家审核后才可进入 `reviewed`；未审核模型答案只能作为负例候选或压力测试题。

### 两层数据合同

**平台观察记录**只描述看见了什么：

- 来源平台、规范化 URL、账号或作品第一方标识、采集时间、采集方式与使用授权；
- 账号自述、可见作品样本、标题或文案、公开互动计数、发布时间与表现形式；
- 选择规则、样本窗口、覆盖率、缺失字段、页面或材料哈希和证据引用；
- 人工观察与事实分离，不能写入“账号定位正确”“受众就是某类人”或“这条因某策略爆了”等未经验证的结论。

**视角纠错金标**描述专家如何改正判断：

- 用户原题与唯一已知事实；模型原答案及其错误关注点；
- 被拒绝的语义主语、尺度或模板，以及拒绝原因；
- 值得比较的候选主语与最终选择；从对象到用途、动作、关系或需求的可观察推导；
- 内容母题、内容世界与表现形式分别记录，禁止把历史故事、真实案例等内容误写成口播、短剧、图文等形式；
- 内容如何归因回生意、当前未知、会推翻判断的新事实、反例与适用边界；
- 来源会话、审核人、审核时间、状态 `draft / reviewed / contested / superseded / retired` 和许可范围。

### 下一验证

- 先从现有会话整理黄金礼品、花店、水果店、工业设备防护包装和宝妈五类纠错记录，但只有用户明确完成纠偏的部分可标为 `reviewed`，其余保持 `draft`。
- 在形成跨窄单品、宽品类、身份不足、专业产品、品牌、服务和本地门店的多样金标前，不启动微调，不训练小策略模型，也不恢复 E13 的案例检索。
- 第一阶段评测只问视角选择器能否选对关注点并守住事实边界，不要求它生成完整起号方案。通过后才允许它路由有界 Skill；Lead 仍保留最终孵化判断权。

## E15 MediaKit 与仓颉变种的账号结构化提取（预登记）

- A33 已复核第四版 Cangjie 派生的 `video-method-distillation`、更接近账号场景的 `video-pattern-learning`、归档账号证据合同，以及本机 `mediakit-cli 0.2.0` 动态 Schema。详细证据见 [A33](audits/A33-account-structured-extraction-feasibility.md)。
- 结论不是“Agent + Skill 路线不行”，而是需要按职责拆开：静态 Skill 不充当孵化总脑；MediaKit 负责单视频感知，受限 Skill 负责带时间证据的语义提取，确定性代码负责跨视频聚合，Lead 保留唯一孵化判断权。
- 候选产物为 `AccountEvidencePack`，至少区分账号身份与采样、单条作品事实、媒体原子、内容/形式/证明/CTA 等推断、跨作品模式、反例、覆盖缺口和未知。所有推断必须回指作品与时间证据。
- 不把公开互动高低自动标成正确定位或训练金标，不从相关性推断爆款原因，不自动生成真实粉丝画像，不把对标结构直接升级成当前项目策略。
- 数据源只接受用户上传、导出、授权访问或人工提供的账号材料；不恢复批量抖音爬虫。MediaKit 云能力只有在素材处理权、云处理同意和费用边界满足时执行。
- 实验使用隔离分支和一个授权账号的小样本，先写合同与失败测试，再比较纯多模态模型和 `MediaKit 原子 + 受限提取器`。只有字段准确性、证据可追溯性和 Lead 最终判断都获得可复核改善，才讨论接入现役主线。

## E15 单视频技术验证结果

- 隔离分支：`codex/e15-account-evidence-experiment`；实验代码位于 `backend/experiments/e15_account_evidence/`，没有注册到 Lead、Gateway、MCP 或 Skill 目录。
- 测试素材为当前仓库内 MIT 许可的 `darcy-proposal-video.mp4`，时长 `8s`。它只能验证单视频技术链，不能代表真实抖音账号验收。
- 本机 `mediakit-cli 0.2.0` 真实执行了本地元信息、云端 ASR、OCR 和场景分割。ASR 返回 `4` 个带时间段；场景分割返回 `1` 段；OCR 返回了一个画面不可见的数字 `5`，被人工核对为误检。这证明 MediaKit 适合当传感器，不适合直接当事实库。
- `doubao-seed-evolving` 的受限多模态提取返回 `7` 个候选信号。首次输出中“摄政时期”被错放在 `observed`；补充“时代、地域、人物身份、关系、意图和来源非直接观察”边界后，同模型复测将文学改编/爱情题材降为 `inferred`，并保留替代解释。
- 新合同只将 `observed` 和 `inferred` 依证据状态分组；`unknown` 保留在单作品记录中，不进入账号模式汇总。`single_support / repeated_support` 只表示样本支持数，不代表因果或成功公式。
- 数据飞轮并非“自动抽取就自动微调”。它现在有两层待审队列：MediaKit 原子的接受/纠正/拒绝/争议，以及模型语义信号的同类审核。两层全部完成、证据包哈希一致、来源权利与训练许可都明确时，才能生成训练候选。
- 当前结论：**单视频技术路径通过，数据飞轮合同可行；真实账号业务验收未通过**。下一步须用一个经授权、多作品且有人工审核的真实账号，同时对比纯多模态基线和 `MediaKit + 受限提取器`。未完成前不接入现役 Lead。

## ADR-007：营销脑 80 分与学习闭环

- 用户明确纠偏：80 分的对象是**营销脑**，不是视频理解。目标是让 Lead 对宝妈、个人、品牌、产品、果农和本地门店都能做出可用的孵化判断。
- 营销脑 80 分至少要做对营销主语、账号定位、内容世界、表现形式、变现承接和事实边界，并避免默认口播、行业模板和编造业务资源。
- 该营销脑位于 `预演 -> 创作 -> 发布回执 -> 复盘 -> 下一轮修正` 中；闭环使项目内的营销判断越用越准，而不是把模型自产内容自动升格成知识。
- 所有权、事实边界、发布审批、第一方回执、幂等对账与训练权利不属于可以打折的 20 分。
- 详细决定见 [ADR-007](decisions/ADR-007-80-point-learning-loop.md)。E15 视频证据实验到此收口并冻结；下一步应将测试和开发重心转回营销脑 80 分验收。

## E16 营销脑 80 分基线与思考诊断

### 评测合同

- 80 分对象是营销脑，不是视频理解。离线评测覆盖营销主语与定位、内容世界、表现形式、商业承接、事实边界、回答当前问题六项，共 `100` 分；总分 `>=80`、营销主语与事实边界均 `>=4/5`、且没有关键失败才算单题通过。该分数只用于离线验收，不进入生产运行时或阻止 Lead 工作。
- 用例覆盖黄金礼品、花店、水果店、工业设备防护包装、仅有宝妈身份、脐橙果农、儿童防晒品牌和县城宠物洗护。只有用户已完整纠偏的黄金礼品标为 `reviewed`；其余是压力测试草案，不冒充用户确认的唯一答案。
- 候选使用现役完整 Lead 提示、GLM 5.2 深度思考、新会话、关闭记忆、Skills、工具、MCP 和子 Agent。评审使用 DeepSeek V4 Flash 非思考模式，分别评价可见业务结果和供应商返回的 `reasoning_content`。
- 原始 `reasoning_content` 只在当次离线诊断内存中使用，不写入结果、产品记忆或训练集；结果只保存哈希和结构化的事实关注、候选主语、选择依据、最早偏移与建议干预层。该思考字段可能是事后解释，因此只能定位假设，不能单独证明因果；必须配合单变量对照。
- 评审若一边列出可见答案中的无依据主张、一边给事实边界高分，确定性聚合器将事实边界封顶为 `3/5`。供应商 `reasoning_content` 诊断只用于定位假设，不再修改可见答案得分：它可能不完整或是事后解释，不能成为独立准入依据。裁判自造的故障标签保存原词并归一为 `unclassified`，不得为迁就裁判无限扩张合同。

### 现役基线结果

- 正向/反向校准先通过：同一 Flash 评审将符合用户黄金推理的答案评为 `96`，将故意写坏的“黄金工艺专家 + 虚构工厂客户 + 10 天/每天 3 条/70%”评为 `31`，并抓到错误主语和事实发明。Kimi 不再参与评测；一次技术链路分数不纳入基线。
- 首次全量运行在裁判格式错误处停止；第二次保存前 `7` 题后，宝妈诊断使用合同外标签而停止。评测器增加单题恢复与保守归一后只补跑宝妈，没有重跑已保存候选。原始忽略文件位于 `.deer-flow/marketing-brain-eval/e16-glm-active-baseline-v2*`。
- 早期曾让思考诊断标签直接封顶可见答案分数，由此得出 `82.8 / 4题通过` 的中间计算；该算法混淆了“诊断假设”和“用户看到的结果”，现已作废。按当前可见答案规则重算为均分 `84.6`、自动 `6/8` 通过，但自动裁判把已经用户纠正为错误的水果店“选品人/本地店”模板判为通过，因此这个数字也不具备产品验收效力。现役营销脑仍未完成 80 分人工验收。
- 水果原始思考在比较语义主语前就调用“高频低客单、本地 3-5 公里、可信选品人、社区店/供应链”行业先验；随后虽注意到水果本身内容宽，最终仍被熟悉起号模板覆盖。病根是行业模板提前获得决策权，不是缺少水果知识。
- 工业包装可见答案正确进入设备安全抵达与风险世界，但补造几十万到几千万设备、出口海运、标准和行业范围；果农把稀缺性、全年生产节律及具体月份当成已成立优势；宠物店默认问题宠物、顾客素材和洗护画面可拍。它们证明“营销主语局部正确”仍不能抵消事实越界。
- 自动裁判漏掉黄金答案末尾的 B/C 与工厂/门店分叉，也曾给列出多项无依据主张的工业题事实边界 `5/5`。所以自动分只用于筛查，用户/人工复核仍是最终验收者。

### E16-R1 角色注意力启动词（预登记）

- 假设：现役角色中的 `MCN 孵化总脑` 可能在模型开始语义重构前先激活行业“起号方案”分布。候选只把这一处替换为 `营销推演与内容孵化总脑`；其余系统提示、模型、采样、问题、上下文和评审完全相同，不增加方法、知识、步骤、示范、Skill、子 Agent 或输出合同。
- 首轮只跑水果店、工业包装、脐橙果农、宠物洗护四个当前失败题，加黄金礼品和宝妈两个防回归锚点，共 `18` 次密封调用。候选至少让四个失败题中的三个变为单题通过，黄金和宝妈不得退步，才运行花店与儿童品牌确认；否则冻结候选，生产提示保持不变。
- 改善必须来自最终业务结果和事实边界。只让输出更短、少写内容、换掉 `MCN` 字样、改变思考措辞或取得更高自动分，不算通过。角色词实验若失败，不再围绕该词增加同义角色描述。

### E16-R1 结果与“新媒体运营”对照

- R1 本地密封产物位于 `.deer-flow/marketing-brain-eval/e16-r1-role-attention-v1`。仅把角色改成“营销推演与内容孵化总脑”后，水果仍停在可信选品人/本地店/供应链，工业包装仍补入设备金额和具体行业，果农仍把未核验优势当成已知。宠物洗护有明显改善，但没有达到“四个失败题至少三个业务上改善”的预登记条件。R1 拒绝，未修改现役 Lead。
- R1B 只对水果店把角色换成“新媒体运营总脑”，产物位于 `.deer-flow/marketing-brain-eval/e16-r1b-new-media-role-fruit-v1`。尽管自动分为 `82`，可见答案更早进入本地流量、避坑选品、平台和门店类型套路，未展开水果本身的内容世界。R1B 拒绝，未修改现役 Lead。

### E16-R2 有界主语候选团队（预登记）

- R2 不复制 E01 的三个“各自交完整起号方案”顾问。它只设三个互相独立的窄职责候选器：对象内部世界、用途与关系世界、专业近端任务世界。每个只能交一个主语假设或“不适用”，禁止交付最终方案、人设、平台、表现形式、栏目、执行计划和数字。
- Lead 只获得三张标明为“不是事实或决定”的候选便笺，可采用、修改或全部拒绝，仍是唯一最终判断者。用户只看到 Lead 答案，生产环境不增加固定专家名册、阶段、门禁或第二运行时。
- 止损只先跑水果店，密封为 `3 候选 + 1 Lead + 1 可见结果评分 + 1 思考诊断 = 6` 次调用。只有对象候选明确识别“水果本身已是宽世界”，Lead 最终答案真正展开品种、时令、状态、风味、吃法或消费场景之间的长期逻辑，不再把可信选品人/社区店/供应链当唯一答案，且不补造用户资源与数字，才算止损通过。
- 水果店未形成人工可见改善时立即停止，不跑其他题；通过后才能进入全部八种业务形状的防回归比较。自动分只用于辅助筛查，不能推翻上述用户已确认的水果纠错。

### E16-R2 结果

- 本地密封产物位于 `.deer-flow/marketing-subject-team-eval/e16-r2-subject-team-fruit-v1`。对象内部候选正确识别了“水果本身是宽世界”，但它在同一职责内被要求立即解释商业归因，于是已将宽世界收窄为时令挑选与选果标准。另两个候选分别进入人情送果和挑果避坑，并补入果篮、礼盒、高客单、日常进货、线下门店和社群复购等未知条件。
- Lead 最终输出为“时令鲜食把关人”，并再次展开社区店、供应链、批发零售、亲自进货、社群团购和产地直发等熟悉模板。它把“长期讲什么”、“主体凭什么可信”和“生意如何承接”压成了一个差异化人设词。这不是用户要求的水果内容世界。
- DeepSeek Flash 自动评为 `90`且通过，证明当前自动 rubric 依然会奖励“专业人设 + 信任 + 本地承接”的完整感，不能取代用户业务审核。R2 按预登记止损失败，未扩跑其他题，也未修改生产 Lead。

### E16-R3 四坐标黑板（预登记）

- R3 验证的不是更多“营销方案 Agent”，而是将语义主语与内容世界、账号定位与受众、表现形式约束、商业承接分成四个互不代替的坐标。每个只写已知、当前判断、未知和推翻条件，禁止交付最终方案或为其他坐标补齐空白。
- 内容世界坐标明确不要求主体独占，不因为别人也能讲就否定它；定位坐标不得用差异化人设缩窄内容世界；商业承接坐标不得反过来把内容缩成销售栏目；表现形式在主体条件未知时保持未知。
- Lead 可修改或拒绝任何便笺，但不得用一个“某某人/家/官/手”同时代替四个坐标。该黑板是离线架构实验，不是生产的固定流程、阶段、评分门或专家名册。
- 仍只跑水果店，密封为 `4 坐标 + 1 Lead + 1 可见结果评分 + 1 思考诊断 = 7` 次调用。人工通过条件是：内容坐标与 Lead 都把水果展开为宽阔的长期对象世界，定位、形式和承接各自保持边界，不回退到选品人/把关人/社区店/供应链唯一答案，不补造业务事实。未通过即冻结，不扩跑。

### E16-R3 结果

- 本地密封产物位于 `.deer-flow/marketing-subject-team-eval/e16-r3-coordinate-blackboard-fruit-v1`，自动分 `78`，人工业务止损同样失败。
- 内容世界便笺比 R2 宽，注意到品类、产地、保存处理、时令更替等展开方向，但仍将门店经营和损耗管理混入“长期讲什么”。定位便笺补入社区店主、产地直供商、挑果达人、本地居民、全国电商、自有果园和质检标准等未知假设；表现便笺把实体店面、实物陈列和日常店务都写成已有可拍素材；商业便笺继续展开到店、同城配送、全国冷链、礼盒和清库存。职责分开了，但行业先验没有因此消失。
- Lead 看到水果内容本身可展开，仍将“本地引流/同城或全国发货/加盟供应链”定为必须先回答的根本分岔，因此停止当前营销推演并要求用户先选商业路线。这说明正确中间产物仍会在聚合时被模型更熟悉的行业分类覆盖。R3 冻结，未扩跑、未修改生产 Lead。

### 多 Agent 研究对照

- [OpenAI Agent 指南](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/) 建议先充分发挥单 Agent，只在复杂逻辑或工具过载时分拆；Manager 模式适合仅让一个 Agent 接触用户和控制执行。R2/R3 的 Lead 边界与此一致，但“Manager 模式”本身不保证 Manager 能正确保留中间判断。
- [Anthropic 多 Agent 研究系统](https://www.anthropic.com/engineering/multi-agent-research-system) 使用 orchestrator-worker，让子 Agent 主要并行搜索不同证据方向；这类可外部核验的证据发现与营销主语的主观判断不同，不能直接证明多个同模型顾问会提高孵化决策。
- [LangGraph Graph API](https://langchain-ai.github.io/langgraph/how-tos/state-reducers/) 能以显式 state、nodes 和 edges 实现黑板与可调试交接，但图编排只解决状态传递，不会自动解决语义决策质量。
- [MAST 多 Agent 失败研究](https://arxiv.org/abs/2503.13657) 将失败归类为规格与系统设计、Agent 间错位、任务验证与终止三类，并指出仅改善角色描述或编排难以简单消除这些故障。R2/R3 的本地结果与这个风险一致。
- 因此不再把“加多子 Agent”当成独立干预。下一步先验证单个窄能力产物是否可靠，只有组件本身在多业务形状上通过，才值得讨论是作为子 Agent、Skill 还是结构化工具接入。

### E16-R4 语义内容地图组件（预登记）

- R4 只验证一个可观察中间产物 `ContentWorldMap`：已知事实、语义部件、可变数量的内容世界候选、展开轴、与原业务的关联、边界与未知。它不交付起号方案，不决定人设、受众、平台、表现形式、栏目、实验或成交渠道。
- 四种可选尺度为对象内部 `object_internal`、用途与动作 `use_action`、关系与长期需求 `relation_need`、专业近端任务 `professional_task`；它们是可检查语义坐标，不是每题必须填满的固定阶段。只有身份而没有商业对象时，允许空候选并说明信息不足。

### E16-R8 结果与买方任务研究

- 本地密封产物位于 `.deer-flow/content-world-selector-eval/e16-r8-selector-gold-deepseek-v1`。DeepSeek V4 Pro 在同一地图与同一选择合同下亦选中 `professional_task`，主要依据同样是“加工是用户原话中唯一可确认的动作”和“加工能长期展开且直接展示能力”；它把送礼关系需求降为次要，理由是用户未证明接触终端用户。R8 失败，证明该选择偏差不应归因于 GLM 一家模型。
- [Harvard Business School 对 Jobs-to-be-Done 的说明](https://www.library.hbs.edu/working-knowledge/what-customers-want-from-your-products) 强调营销分析应从人口分组和产品属性转向客户想完成的任务，客户是将产品“雇来”满足需求。[Christensen Institute](https://www.christenseninstitute.org/theory/jobs-to-be-done/) 进一步将该任务定义为特定情境下人或组织想取得的进展，包含功能、社会与情感维度。
- [Ehrenberg-Bass Institute 的 Category Entry Points](https://marketingscience.info/news-and-insights/category-entry-points-in-a-business-to-business-b2b-world) 将营销入口定义为买方进入品类购买情境时触发记忆的内外线索，包括时间、地点、同时发生的事情、动机、情绪与涉及的人。这些买方情境应与主体已有客户事实分开：前者可作为品类语义候选，后者需要证据。
- 用户的黄金礼品纠错、JTBD 与 CEP 三者指向同一个任务通用区分：**卖方如何生产/实现通常是信任证明，买方把产品用来完成的任务、情境或关系进展更可能是营销主世界**。它不是黄金行业模板，但必须保留宽品类、专业买方任务和身份信息不足的反例刹车。

### 商业语义骨架研究对照

- 复合表达并不是词袋。[Shwartz 与 Dagan 的复合名词释义研究](https://arxiv.org/abs/1805.02442)指出，复合成分之间存在需要显化的隐含关系；同一种表面组合可能分别表示材料、用途或发生情境，而且单一固定关系分类存在歧义。它支持先做自然语言释义、保留多个解释与歧义，而不是按关键词权重选主语。
- [Gutman 的 Means-End Chain 原始研究记录](https://cir.nii.ac.jp/crid/1360855571236099712)将产品属性与人所追求的价值连接起来。这里仅吸收“属性、后果/功能、价值不能混为一层”的结构，不把任何高层价值自动判成内容主世界，也不把通用品类语义写成主体客户事实。
- 语言语法主词不能直接等同商业营销对象：经营载体可能在句法上显著，但主体实际经营的是载体中的对象；卖方动作也可能明确，却只是实现方式。因此第五版需要的是可审计的“商业语义骨架”，不是一个通用中文分词器或行业关键词表。

### E16-R11 商业语义骨架组件（预登记）

- 所有字段区分 `explicit` 与 `lexical_semantics`：前者只允许用户原话事实，后者用于复合表达关系、品类构成功能和通用买方进展，必须明确不是主体已有客户事实。只有身份而无商业对象时，`offer_object` 必须为 null 并返回 insufficiency。
- 冻结同一完整提示、Schema、GLM 5.2、思考开启、无 Lead/记忆/Skill/工具/子 Agent/LLM 裁判、原始思考不落盘；默认提供方超时 `180` 秒。按水果、黄金礼品、工业设备防护包装、宝妈顺序各运行 `1` 次，任一业务语义失败则停止。

- 工业包装通过条件：明确被服务对象是工业设备，防护是目的，包装/方案适配是专业服务或动作，买方进展停在设备安全流转、风险控制或交付确定性；不补造金额、运输方式、标准、职位和事故。宝妈通过条件：只有身份与做号意图，无法解析商业对象，返回 insufficiency，不能套育儿/母婴/家庭/女性成长。
