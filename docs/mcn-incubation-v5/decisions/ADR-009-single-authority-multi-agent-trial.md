# ADR-009 单一孵化决策权下的多 Agent 试验

## 背景

第五版必须具有一家 MCN 的孵化能力，但第四版已证明，多个提示词、角色、Skill、中间件、评分器和阶段同时拥有语义控制权时，模型会在冲突指令中生成看似完整、实则无依据的方案。

同时，OpenAI、LangChain、Anthropic 和 Google 都提供了由中央协调者调用有界子 Agent 的官方模式。DeerFlow 现有 `task` 委派已符合这一结构。

## 候选决定

保留 DeerFlow Lead Agent 的唯一孵化决策权、用户对话和项目线索；将专业子 Agent 仅作为 Lead 可选调用的 `agents-as-tools`。

不使用 `handoff`，不让子 Agent 接管对话或孵化决策。不强制委派；Lead 只在专业能力或上下文隔离的预期收益显著高于成本时使用。

## 权限合同

| 能力 | Lead Agent | 专业子 Agent |
| --- | --- | --- |
| 与用户对话 | 是 | 否 |
| 保留项目多轮线索 | 是 | 否，一次性上下文 |
| 最终孵化判断 | 是 | 否 |
| 读项目事实、证据和方法 | 是 | 按白名单只读 |
| 写项目状态 | 受所有权和审批约束 | 否 |
| 询问用户 | 是 | 否 |
| 再委派 | 按运行上限 | 否 |
| 不可逆操作 | 需显式审批 | 否 |

## 首试

只在孵化评测器内临时注册一个只读 `incubation-evidence-researcher`：

- 只能读项目事实、项目证据和方法上下文。
- 输出证据、反转性未知、条件化选项、无依据假设和局限，不输出最终策略。
- 总委派上限为 1，子 Agent 图步数、Token 和超时显式受限。
- 密封架构模式、权限、工具面、输入输出哈希和实际轨迹。

## 2026-08-12 候选 B

A37 的单证据研究员真实运行没有触发 `task`，因此没有验证专业分工。A49 的单张用户思维蒸馏卡又出现栏目复写和业务失败。用户随后明确要求改测一个真正的 MCN 孵化团队：定位、受众、内容世界、表现形式和商业化各由一个只读子 Agent 作板块推演，Lead 解决冲突并输出唯一最终判断。

该候选只在 `run_incubation_agent_eval.py --subagent-mode incubation-team` 的复制配置中存在。五个角色各恰好调用一次是隔离实验的操纵变量，用来避免再次产生“角色存在但未触发”的无效样本；它不修改上文“生产不强制委派”的决定，也不是固定孵化阶段。角色可按任意组合分批，并发批次没有业务先后。

候选 B 不是下文所拒绝的“多孵化专家并列最终决策”：子 Agent 只能对自己的板块提交有条件的判断、备选和反证，不能投票、打分、写状态、对话用户或形成完整方案，Lead 仍有唯一最终决策权。

一次团队运行只能验证绝对业务可用性和执行链路，不能证明改善由多 Agent 引起。任何因果优越性结论都还需要一个携带同等业务边界的单 Lead 匹配对照。

候选 B 的 M01 真实运行已于 2026-08-12 完成：五个角色 `5/5` 执行，43,667 Token，技术通过。答案改善了默认露脸口播和内容/形式混淆，但补造 19.9/99 元、每周 16 单、周更 2 条和制作耗时，人工业务拒绝。该结果不接受 ADR，也不改生产；详见 `evidence/2026-08-12-m01-five-board-team-trial.md`。

## 验证门槛

候选只有在同模型、同案例、同 Lead 合同与同评审口径下，显著改善最终孵化判断才能保留。不以调用次数、固定工具轨迹、角色内部一致或文本长度为通过依据。

至少要求：

- 不增加无依据的表现形式、平台、资产、价格、产能和阈值。
- 更准确地识别会改变路线的主体信息和证据缺口。
- Lead 仍是唯一用户可见判断者，子 Agent 无写入和越权。
- 延迟和 Token 增量与业务改善相匹配。

一个案例可以拒绝候选，但不能宣布架构胜者。

## 备选方案

- **永久只使用单次 Lead 模型调用**：成本低，但未验证能否解决证据密集任务的上下文与注意力问题。
- **多孵化专家并列决策**：拒绝，会恢复第四版的多控制源。
- **固定阶段工作流**：拒绝，会让信息不全的项目被迫填满。
- **子 Agent handoff**：拒绝，会让孵化决策权和用户线索转移。
- **引入第二 Agent 框架**：拒绝，DeerFlow 已经提供所需原语。

## 后果

积极后果是可在不改变孵化决策权的前提下扩大有界研究能力，并复用 DeerFlow 现有权限、追踪和恢复能力。

负面后果是更高的 Token、延时和协调复杂度，且子 Agent 可能只会重复 Lead 或放大错误。因此该 ADR 保持 `proposed`，实验候选不默认进入生产。
