# ADR-012：拒绝独立样本薄语义格进入生产

- 状态：已决定
- 日期：2026-08-14
- 依据：A45、A46、A47、E31、E32

## 决定

不把 E32 的两调用薄语义格注册为 Lead 阶段、Tool、Skill、子 Agent、中间件或 Gateway 路径。保留离线脚本、新留出案例、候选召回/最终收敛分诊和四组对比结果，作为下一次架构选择的失败证据。

## 原因

E32 的工程边界明显比 E31 健康：七题全部一次通过两阶段 JSON 合同，没有使用修复；总用量从 `43,017` 降到 `20,394 tokens`，总耗时从 `476.932s` 降到 `250.308s`。薄结构解决了合同面和成本问题。

但它没有通过业务线：候选召回为 `5/7`，最终收敛为 `3/7`，四组最小对比只通过商务礼品的材质替换一组。开茶叶店与卖茶叶只改变了经营表达，结果却从“茶叶”漂移到“饮茶实践”；两个咖喱中间产品都稳定地选错为烹饪实践；银饰第一阶段已有对象根，最终仍选了设计与手作过程。

所以病根进一步收窄了：模型并不缺联想，它常常已经生成正确对象候选；当对象与使用/生产过程同时存在时，收敛优先级仍偏爱“有人、场景、规则和过程”的动作或实践词。减少中间字段没有改掉这个选择先验。

人工事实复核也失败：银饰只已知“设计”，答案却把手作和加工过程当作已有能力；木质礼品候选擅自建议展示定制案例；咖喱答案为了补足返回路径加入了未证实的优质、便捷和不可或缺。即使自动分数达标，这一条也会触发止损。

## 保留与拒绝

- 保留薄且可空的中间合同，作为离线诊断工具；不把它变成必经流程。
- 保留“商品 -> 直接用途 -> 赠礼关系实践”能跨材质迁移的正向证据。
- 保留最小对比，因为它可以发现单题看不出的漂移和“稳定地选错”。
- 拒绝继续往 E32 提示上叠理论、行业示例、评分、第三调用或固定子 Agent 阵容。
- 拒绝用“饮用/烹饪/制作不得为根”这类关键词硬门；送礼本身就证明某些行为确实可以是根。

## 下一边界

新茶叶、银饰和咖喱标签先由用户确认业务口径。若口径成立，后续只能另行预登记新留出集，测试“先看一组最小变体中什么应保持、什么应变化，再选根”的关系式注意力转移。它必须替换 E32，不能叠在 E32 后面；通过也仍需生产探针，不能直接进 Lead。

## 后果

现役 Lead、`analyze_business_semantics`、`explore_content_worlds`、模型配置与 Gateway 均保持不变。第五版获得了更准确的故障位置和一组新标注，但尚未获得可上生产的语义选根升级。
