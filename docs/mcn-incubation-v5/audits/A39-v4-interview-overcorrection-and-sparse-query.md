# A39 第四版访谈过度修正与第五版稀疏首问审计

## 结论

第五版这次失败与第四版是同一个业务问题：用户只给出一个行业或阶段标签时，Agent 还没有足够主体事实来决定受众、表现形式、内容供给和变现路线。真正缺失的是**何时可以承诺一条路线的判断**，不是一张更完整的问卷，也不是更多行业知识。

第四版最初得出了正确结论：标签不是主体，下一问应当具有决策价值并跟随用户回答。但它随后把这项判断编译成关键词识别、首次使用拦截、独立访谈状态、强制工具调用、结构化合同、校验器和 Writer Brain。每次模型失败又增加一个字段、合同或测试，最终事实、创作、制作和商业同时控制模型。第五版不能为了让模型多问一句，再恢复这条运行链。

第五版当前又摆到了另一个极端。Lead 的薄合同要求只问会反转建议的事实，但通用澄清段同时强调“可逆营销判断不要变成问卷，应声明假设并继续”。真实模型在稀疏问题中把后一句理解成“不必提问”，随后用假设补齐整套方案。**不把缺失信息变成硬门，不等于可以用假设替代决定路线所需的主体事实。**

## 第五版真实失败

右侧真实会话中，用户只问：“我是一个做黄金礼品加工的，你有什么起号的建议吗”。Agent 正确列出了 B 端或 C 端、差异能力、是否露脸、工厂和定价等未知，却在思考中把“可逆的营销判断不用做问卷”作为继续输出整套方案的理由。

最终答案无来源地加入每周五小时、B/C 双路线、四类内容比例、平台、投流金额、七天窗口、咨询阈值和客单价。它把未知列出来了，却没有让未知参与决策。这不是“条件化判断”，而是先完成模板，再把未知附在模板旁边。

当前 36 案例评测也存在覆盖盲点：所有案例先写入项目事实，再用项目 ID 请求 Agent；即使极冷启动 N01 也已知每周十小时。它没有覆盖“普通聊天入口只有一句行业描述、没有项目账本”的稀疏首问，因此此前测试不能证明这个入口成立。

## 正确边界

需要区分两个问题：

1. **请求能否继续**：可以。Agent 应先给出仅由现有事实支持、对多种可能答案都稳健的观察，并指出最关键的不确定性。
2. **路线能否承诺**：未必。受众、变现、表现形式或内容供给会被未知事实显著反转时，只能保留条件化候选，并自然询问当前信息增益最高的问题。

这不是阶段机。用户给出的信息已经足够、用户明确只要脑暴、用户拒绝继续回答，或当前任务只是改脚本、分析链接、制作素材时，Lead 都可以直接推进。判断对象是最终业务承诺是否有依据，不是有没有调用某个提问工具。

外挂知识也不能代替主体事实。方法卡可以帮助 Lead 识别哪些未知会反转路线，外部证据可以说明市场与对标，项目事实账本可以保存用户真实回答；三者都不能替用户回答“谁在购买、最强利润池、本人表现能力和可公开证明是什么”。

## 第五版决定

1. 先冻结失败评测，再修改行为。首组应同时覆盖稀疏黄金加工首问、信息充分的同主体请求、明确具体任务、用户拒绝补充信息和新事实到来后的修订。
2. 评测只看最终业务行为：是否用未知补造完整路线、是否保留稳健观察、是否识别真正会反转路线的信息、是否能在新证据后修订。不得要求固定提问轮数、固定问题文本或固定工具轨迹。
3. 不新增独立访谈 Agent，不使用关键词拦截，不强制 `tool_choice`，不建立 `continue/ready/stop` 访谈状态，也不把字段完整度作为继续条件。
4. 不恢复第四版本体 Schema、语义距离校验器、Writer Brain、事实/故事合同或输出改写中间件。它们只能作为失败证据和方法来源。
5. 后续若调整提示词，只允许澄清“可以继续提供价值”与“可以承诺路线”的区别；不得加入行业模板、问题清单、配额或样例答案。真实模型仍不通过时，先重新审查评测和上下文冲突，不继续追加规则。
6. `incubation_record_subject_answer` 继续只保存已经发生的真实问答，不决定何时提问，也不因此变成 onboarding 工作流。
7. 本轮只完成审计与回归护栏，不修改 Lead 运行时，不发起新的付费模型调用，也不把黄金礼品案例记为通过。
