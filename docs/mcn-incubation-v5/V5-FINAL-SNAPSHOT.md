## 第五版留下了什么

第五版最重要的成果不是一套可直接整体迁移的运行时代码，而是一组经过失败对照逐步收窄的业务结论、评测方法和可复用原语：

- 一个 Lead 保留最终新媒体判断权；子任务、工具和模型调用只提供有界材料。
- 用户原话、外部证据、模型解释、创意假设、未知和真实结果必须分开。
- 商业语义需要区分经营载体、商业对象、词法主词、修饰关系、用途与主体动作。
- 内容地图回答长期讲什么，表现形式回答怎么呈现，两者不能混写。
- 内容世界既允许向上连接，也必须先检查对象本身是否已是完整世界。
- 类别级地图不足以自动长出具体选题；人物、作品、事件等命名候选需要独立发现和取证。
- E39 证明“先阅读、再立题”在人工作品质量上有明显方向性收益，但冻结门槛未过，不获准直接上线。
- E40 证明“命名候选 -> 搜索 -> 阅读 -> TopicBrief”能从宽泛目录长出丘吉尔、卡斯特罗、古巴禁运等具体入口，但未召回用户金标人物，仍不获准直接上线。
- 真正应带入第六版的是共享阅读理解内核，以及语义、地图、选题对同一理解记录的不同投影。

## 不整包迁移

以下内容保留在第五版作为证据，不得因为文件存在而默认进入第六版运行时：

- 当前 `lead_agent/prompt.py` 中累积的 MCN 身份、营销义务和内容地图长路由说明；
- 当前商业语义与内容地图工具的完整实现；
- E28-E40 中未通过预登记的候选架构；
- 固定阶段、固定候选数、固定问题数、评分门、实验门和工具轨迹测试；
- 旧 MCN 包、旧浏览器缓存、Python bytecode 和 `.deer-flow` 评测运行产物；
- 用户金标案例答案、历史人物清单或行业关键词补丁；
- 任何 API Key、Cookie、StorageState 或本地凭据值。

## 第六版起点

第六版从官方 DeerFlow `cd87968a` 新克隆，不覆盖或重写第五版。允许为产品融合修改核心，但每项核心修改必须有单一职责、失败测试和台账来源，不能以“兼容官方”为新硬门，也不能把业务规则重新堆入总提示词。

首个垂直切片固定为：

```text
SourceItem
-> ComprehensionRecord
-> BusinessSemanticView / ContentWorldView / TopicBrief
```

共享记录只承载来源、字面观察、实体角色、关系边、状态变化、派生解释、反证和未知。三种投影分别承担商业表达释义、内容世界组织和具体立题，不相互冒充最终账号方案。

## 迁移纪律

- 先迁测试、金标说明、证据合同和审计结论，再根据新边界重写实现。
- 第五版仓库保持可运行、只读参考；第六版使用独立目录、独立分支和独立本地端口。
- 新旧版本使用相同模型和留出案例做对照，不在已经看过答案的雪茄案例上继续调参。
- API Key 仅从本地未跟踪配置迁移，迁移后执行忽略规则与密钥扫描。
