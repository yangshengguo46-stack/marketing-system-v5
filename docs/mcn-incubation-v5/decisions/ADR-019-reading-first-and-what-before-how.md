# ADR-019：先阅读理解，再决定说什么，最后处理怎么说

- 状态：accepted_for_research_not_runtime
- 日期：2026-08-14
- 依据：A54、E38、A55、FrameNet、AMR、HotpotQA、ReadAgent、Project Debater、STORM、Reiter-Dale NLG 架构

## 决定

第五版将“语义识别 -> 内容地图 -> 选题生成”视为同一个开放世界营销阅读理解内核的三个可审阅产物，不再将它们当作三个争夺决策权的 Agent。

后续内容生成必须继续分层：

```text
TopicBrief
-> MessagePlan（要说什么，论据如何支持命题）
-> BaseDraft（不带平台和表演套路的中性母稿）
-> PresentationAdaptation（口播、短剧、情景剧、图文、纯素材等怎么说）
```

当前只审计和验收阅读理解层。在对象、关系、地图路径、支撑事实和中心命题的未见案例通过前，不实现生产 `MessagePlan`，不优化表现形式。

## 原因

当前失败多发生在理解层：主语选错、边的类型改写、人物行为对象跟错、共现写成因果、解释冒充事实。在这些问题上叠加口播感、镜头、平台套路或卖货要求，只会分散注意力并让流畅表达掩盖语义错误。

FrameNet 与 AMR 支持先表示情境、参与者和关系；HotpotQA 支持将答案与跨文本支撑事实联合验收；Project Debater 和 STORM 展示了从资料理解、主张/证据整理到叙事/文章的分层；经典 NLG 架构则明确将内容决定与表层实现分开。

## 保留的工程约束

- Lead 保留最终判断权，中间产物不是硬门。
- 语义、地图和选题共享同一个事实边界，但不允许下游反向改写冻结根或证据。
- 不强制标准 FrameNet/AMR 标签，不新建巨型语义 Schema。
- 不因 STORM 使用多视角 Agent 就新建固定多 Agent 队伍。
- 不安装 STORM、Project Debater 服务或新知识库；开源代码采用另行审计。
- 不用表达流畅、口播感或篇幅完整代替阅读理解验收。

## 下一步

下一个实验应是阅读理解评测集，而不是文案风格器。它将已有用户纠正案例与新留出案例分开，分别检查对象、框架、地图边、跨文本支撑事实、中心命题和未知边界。阅读层通过后，才预登记 `MessagePlan -> BaseDraft` 中性表达实验。
