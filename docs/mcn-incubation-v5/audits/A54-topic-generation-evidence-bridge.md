# A54 选题生成与证据桥审计

## 用户纠正后的模块边界

第五版当前要解决的三层不是同一件事：

```text
语义识别
-> 决定业务表达中的商业对象、词法主词、修饰和可能的内容主语

内容地图
-> 读取已经选定的根，沿种类、时间、空间、文化、人物、事件、冲突和跨领域连接展开

选题生成
-> 从地图中的一条具体路径，提炼本次值得讲的关系、问题或命题，并为事实取证
```

内容地图只证明“有这条可研究路径”，不证明这条路径已经构成选题。选题生成也不重新选择账号主语、不扩写整张地图、不决定口播/短剧/图文等表现形式，不设计卖货和经营。

## 海鲜案例的正确拆分

用户给出的路径是：

```text
海鲜
--下位类别--> 牡蛎
--出现在作品中--> 《我的叔叔于勒》
```

这还不是一条完整因果链。至少要区分四种关系：

1. `海鲜 -> 牡蛎` 是类别关系。
2. `牡蛎 -> 《我的叔叔于勒》` 是作品中的实体出现关系。
3. `吃牡蛎 -> 父亲注意到开牡蛎的人 -> 认出于勒` 是文本中的叙事触发链。
4. `认出贫穷的于勒 -> 家人从期待转为躲避` 才是人物反应的故事因果。

不能写成“牡蛎导致亲情冷漠”。牡蛎在这里更准确的功能，是把一家人想表演的体面消费与贫穷的亲属放进同一个场景，触发身份揭露，并让原有价值观变得可见。

Project Gutenberg 收录的法文原文可以核验：父亲先被船上吃牡蛎的体面姿态吸引，随后发现开牡蛎的水手像于勒；确认身份后，家人担心被认出并改乘另一条船。仅凭原文可以支持情节链与文本功能分析，但不能未经作者材料就断言“莫泊桑本人为什么偏偏选择牡蛎”。后者只能写成解释性阅读，不得伪装成作者意图事实。

## 选题如何成立

地图路径进入选题生成后，模型需要完成四个动作，但它们不是固定的用户工作流：

1. **关系显化**：说明路径中每条边是什么关系，禁止把出现、象征、触发和现实因果混写。
2. **命题提炼**：把关联改写成一个有张力、可讨论、可被证据支持的中心问题或判断。
3. **来源取证**：为作品情节、人物、历史、原话、数字和现实事件找到可追溯来源。
4. **收敛交付**：形成一个选题简报；只有用户继续要求写稿时，才交给文稿创作。

本例可以收敛为：

> 一盘牡蛎，怎样把《我的叔叔于勒》中“有钱亲戚”的期待，瞬间变成了对贫穷亲属的躲避？

核心判断可以写成：

> 牡蛎不是小说的主题，却是身份揭露的叙事机关：一家人本想借吃牡蛎靠近体面，恰恰在这场体面消费中认出了落魄的于勒，于是亲情是否成立，暴露为对方能带来财富还是负担的条件判断。

这一命题同时满足：从海鲜地图自然长出、与原文事件相连、有明确冲突、可继续研究，也不需要把产品或成交塞进文章。

## 模型与联网的职责

不是“模型记忆”与“联网搜索”二选一：

| 职责 | 首选执行者 | 原因 |
| --- | --- | --- |
| 从地图路径召回跨域关联 | 模型 | 参数知识适合低成本发散候选 |
| 判断关联是出现、类比、触发、冲突还是因果 | 模型，接受证据纠正 | 这是语义与叙事解释任务 |
| 提炼中心命题、反题和观看张力 | 模型 | 这是创意收敛，不是检索排序 |
| 核对作品情节、人物、原话、历史、数字和当前事实 | 搜索与原始来源 | 模型记忆不能提供可靠出处和版本边界 |
| 区分文本事实、解释性判断和创意假设 | 结构合同加 Lead | 防止推断伪装成事实 |
| 最终选题判断 | Lead | 工具和子任务不拥有孵化决策权 |

RAG 研究支持用外部非参数记忆改善知识密集任务的具体性、事实性和来源追踪；Self-RAG 进一步指出，不分任务地固定检索反而可能引入无关材料，因此应按需检索。ReAct 支持让推理与外部行动交替，而不是先把整个互联网塞进上下文。Anthropic 的 Contextual Retrieval 说明精确词匹配与语义检索互补；像“牡蛎 + 作品名”这种明确实体，应先做精确检索和原文读取，隐含主题关联才需要语义检索。

## 首版检索策略

首版不建立向量数据库、知识图谱数据库或 GraphRAG 索引：

- 用户已经给出作品、人物、事件或链接时，先用现有 DeerFlow `web_search` 与 `web_fetch` 精确检索，优先原文、官方资料、论文或第一方记录。
- 模型只给出关联但没有证据时，把它当 `candidate`，生成窄查询后再核验；搜不到就保留为待研究，不能写成事实。
- exact/BM25 类检索处理作品名、人物名、术语和原话；语义检索只作为隐式主题召回的补充。
- 当本地已经积累大量有来源全文，且相同资料被重复检索时，再比较关键词、混合检索与 GraphRAG local search。GraphRAG 的实体、关系和原文片段联合检索适合大型私有语料，不是当前单个命名作品的前置依赖。
- 不预计算“所有海鲜与所有文学作品”的连接。那会组合爆炸，也会把弱共现误当好选题。

## 候选模块合同

下一候选暂称 `TopicBridge`，只输出一个薄的 `TopicBrief`：

```text
TopicBrief
  content_root              已冻结内容根，例如“海鲜”
  map_path                  已选地图路径及每条边的关系类型
  topic_question            本次真正要回答的问题
  central_premise           可争论、可取证的一句话中心判断
  narrative_or_explanatory_mechanism
                            关联为什么成立，而不只是“二者都出现过”
  evidence_claims           每条待用事实及所需来源
  interpretation_claims     明确标记为解释，不冒充原作者意图
  counter_reading           一个可能推翻或限制中心判断的替代解释
  unknowns                  当前没有证据的事项
```

合同不要求固定候选数、评分、篇数、天数或实验。用户只给一条路径时默认把这一条做深；用户明确要求批量选题时才发散多个候选。选题通过后，写稿模块可以读取 `TopicBrief` 和证据包，但不能倒过来改写内容根或伪造来源。

## 第四版可复用与拒绝项

第四版“编导因果桥”已经提出三个有价值的原语：联想来源只贡献关系/因果边、故事与商业连接分开、通过替换测试判断一个对象是否真的参与因果。后续版本还修复了“填满槽位却没有有效目标和代价”的部分问题。

但其实现不能迁移：

- 一次选题被强制扩成完整人物故事、表演与生产合同。
- 固定人物、触发、策略、反馈、二选一、代价和状态变化会诱导模型补造不存在的事实。
- 旧独立评审只得 `62/100` 并直接失败，明确指出自由文本事实污染、远联不足和机械填槽问题；后续单例升到 `85` 也依赖约 `10 KB` 输入和大量结构字段，不能证明适合通用选题运行时。

第五版只吸收“关系边、替换检验、事实/假设分离”三个思想。替换检验是可选诊断：若把牡蛎替换成任意食物后，身份识别、体面消费与贫穷劳动者的同场冲突是否仍完全不变？如果改变，说明牡蛎至少承担具体叙事功能；这仍是文本解释，不是现实市场的 Pearl 式因果证明。

## 多版本优点合并

| 来源 | 保留 | 不保留 |
| --- | --- | --- |
| 现役语义工具 | 用户原话、事实边界、按需调用 | 把语义材料当最终账号判断 |
| 现役内容地图 | 冻结根、真实展开轴、跨领域待研究连接 | 让地图容量反过来裁决根 |
| E31-E34 | 候选召回与最终收敛分开观察、最小对比诊断 | 理论大对象、固定角色和多阶段硬流程 |
| E35 原版 | 来源对象、内容世界、发动机、注意力入口的丰富表达能力 | 用系统自写标签代替用户业务验收 |
| E37 | 候选 id 绑定、节点必须挂在冻结根上 | 用七轴丰富度证明语义正确、未核验具体事实 |
| 第四版因果桥 | 关系/因果边、替换检验、故事与业务分离 | 巨型 Schema、固定槽位、编造故事与生产条件 |
| RAG/GraphRAG 研究 | 按需检索、原文证据、实体关系和片段可追溯 | 无条件检索、首版即建大型向量/图数据库 |

## 下一步验收

先在隔离实验中比较三个同模型候选，不修改现役 Lead、语义工具和内容地图：

1. 仅凭模型直接从路径生成选题。
2. 薄 `TopicBridge` 先生成关系命题，再读取人工冻结的一手证据包。
3. 薄 `TopicBridge` 自己提出检索需求，Lead 使用现有搜索/抓取工具补证后收敛。

评测至少覆盖对象到文学、对象到历史、对象到现实事件、对象到人物、对象内部冲突和用户自带材料。分别检查路径忠实、关系类型、命题强度、事实可追溯、解释/事实边界、非机械模板和是否越权写表现形式或经营。先由用户校准海鲜案例，再使用未见案例；不在一个案例上反复调到通过后宣称泛化。

## E38 开发探针

隔离候选 `backend/experiments/e38_topic_bridge/generate-content-topic` 已按薄 Skill 形状实现，没有注册到现役 Skill 目录、Lead、Tool、MCP 或中间件。第一次 GLM 真实探针抓到了“借牡蛎表演体面，却遇见落魄亲属在开牡蛎”的核心冲突，但同时改写了原地图边、猜测了作者意图，并把人物逃避对象从于勒错写成牡蛎。

上述三类问题先进入失败测试，初跑为 `3 failed / 1 passed`；收紧 Skill 后为 `4 passed`，并通过 Skill 包验证。第二次同模型探针保留了“海鲜 -> 牡蛎 -> 作品”原始路径，把叙事触发单独列为派生关系，正确追踪了躲避于勒的人物行为，也没有越界生成表现形式、卖货、平台或完整文稿。

人工复核状态为 `development_case_pass_with_precision_caveats`，不是生产通过：输出仍有“中产体面”证据强度过高、“完全寄托”过度绝对、引入未在冻结证据包中的家庭期待标签等精度问题。详细证据见 E38；下一步必须换未见路径，不继续用这一题叠规则。

## 结论

选题生成是语义识别与内容地图之后的独立第三层。首选候选形状是**薄方法 Skill + 现有搜索/抓取工具 + Lead 收敛**，而不是新知识库、固定多 Agent 队伍或第三个大 Schema。该决定只确定实验边界，尚未注册生产能力；详见 ADR-018。
