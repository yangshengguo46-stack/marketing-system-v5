# A44 两步式内容地图预登记

## 待证伪假设

E29 的单次调用同时竞争观众根、发动机、入口和展开轴，导致下游词污染观众根，并增加大 Schema 漂移。候选改为两个有界调用：

1. 骨架调用只产出来源对象、观众世界、内容发动机和注意力入口。
2. 展开调用只接收已经冻结的骨架与原证据，只能产出带父引用的展开节点，Schema 中没有改写骨架的字段。

本假设只声称分离注意力可能提高稳定性，不预设它一定优于 E29，也不声称两步就是最终 Agent 架构。

## 固定控制

- 模型：`glm-5-2-260617`，thinking 开启，`low` reasoning effort。
- 案例：沿用 E29 的黄金礼品、水果店、海鲜源头、重庆火锅底料、腕表与医美六例，不增删金标。
- 模型不可见验收标签、禁止答案与审阅说明；它们只在两个调用都结束后运行。
- 每例最多两个主调用；全组骨架和展开各共享最多一次 Schema-only 修复，总上限 `14` 次供应方调用。
- 不允许用金标修复业务答案，不做模型裁判、不读取记忆、不加载 Skill、Tool、MCP 或子 Agent，不写生产状态。
- 第二步不能重新命名来源对象、观众世界、发动机或入口；任何展开节点必须挂到冻结的观众世界或已存在发动机。

## 通过与止损

- 架构竞赛通过：零合同失败，四个用户纠正案例全部通过，六例总成绩至少 `5/6`。
- 任一用户纠正案例的来源对象或观众世界错误、任一合同失败、或总成绩低于 `5/6`，候选不进入生产探针。
- 即使架构竞赛通过，本轮也不直接修改 Lead 或现役工具；仍须另行做真实 Gateway 生产探针后才能签署采用决策。
- 冻结完整复测只跑一轮，不拼接局部最佳答案，不为失败案例补行业规则。

## 冻结复测结果

- 运行：`e30-two-step-final-six-20260814-01`。
- 冻结提示哈希：骨架 `926c5cba...df5e`，展开 `b5df092e...d366`。
- 成绩：`3 passed / 2 failed_business / 1 failed_skeleton_contract`，未达到预登记阈值。
- 通过：水果 `水果 -> 水果`、海鲜 `海鲜 -> 海鲜`、腕表 `腕表 -> 腕表`，自然结构轴也完成展开。
- 黄金：来源对象为黄金礼品，但观众世界仍停在黄金礼品，继续围绕工艺、纯度、选购与预算，没有完成 `礼品 -> 送礼/人情往来` 的营销语义跃迁。
- 医美：正确得到 `医美 -> 变美`，但骨架只保留人物地域与日常保养两个发动机，漏掉抗衰/年轻化和外貌观念两组已审阅信号。
- 火锅：骨架输出的注意力节点漏掉 `basis`；全组共享的一次骨架 Schema 修复已经被黄金使用，因此按固定预算记录合同失败，展开调用没有发生。
- 共发生 `12` 次供应方调用，其中骨架修复 `1` 次、展开修复 `0` 次；合计 `38,319 tokens`、`450.133s`。隐藏思考只保存组合哈希。

## 复盘

与 E29 的 `1/6`、两个合同失败相比，两步式提升到 `3/6`、一个合同失败。水果、海鲜和腕表同时得到正确骨架与完整展开，医美也不再被展开词污染为“面部年轻化”。这一结果与“分离调用减少部分注意力竞争”的机制假设一致，但单轮六例不能独立证明因果。

但最关键的黄金题仍失败，证明调用编排不能替代“从产品到用途、从用途到社会行为”的营销判断。继续把一次调用拆成更多阶段，只会增加费用和合同面，不构成新的业务能力。根据预登记，本候选停止在离线证据，不进入 Gateway 生产探针，不修改 Lead 或现役工具。
