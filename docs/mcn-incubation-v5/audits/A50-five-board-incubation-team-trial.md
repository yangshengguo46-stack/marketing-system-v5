# A50 五板块孵化团队试验

## 结论

用户在 2026-08-12 明确纠正了 A49 之后的下一步：当前优先假设不再是继续蒸馏用户个人思维，而是直接利用 DeerFlow 已有多 Agent 底座，组成一个真正的 MCN 孵化专业团队，一人负责一个板块。

本轮建立的候选由五个专业子 Agent 和一个 Lead 组成：定位、受众、内容世界、表现形式、商业化。五个专业角色对同一项目并行提出板块判断、备选和反证；Lead 保留唯一最终决策权，负责解决板块冲突并形成一个面向用户的答案。

这不是线性阶段，不是五套 SOUL，也不是把五个答案投票、打分或拼接。不得投票、不得打分、不得直接拼接。角色不能写业务状态、不能提问用户、不能再次委派、不能执行浏览器或发布操作。该候选目前只存在于评测器的复制配置中，属于评测专用架构试验；生产配置和生产 Lead 提示词均未修改。

离线实现和测试通过后，M01 五板块真实运行技术 `1/1` 成功：五个角色均完成，使用 43,667 Token，耗时 171.606 秒。它改善了默认口播和内容/形式混淆，但仍补造 19.9/99 元、每周 16 单、周更 2 条和单条 1 至 2 小时等关键经营事实，人工判定 `business-rejected`，生产保持不变。

团队提示中显式写入了五个业务板块和内容/形式边界；单次团队运行只能看绝对业务质量，不能把改善因果归于多 Agent。因果比较还需要携带同等业务提示的单 Lead 匹配对照。

## 为什么重新打开多 Agent 假设

A37 首试只提供一个只读证据研究员，并且 Lead 实际没有调用 `task`。那次运行只能证明“可选单研究员未触发”，没有验证“多个专业人员分别做深一个孵化板块后再综合”的用户假设。

A49 又证明，一张紧凑蒸馏卡会被模型照着栏目复写，水果有局部改善，黄金礼品仍未抓住礼品和送礼这个语义主语。继续把更多判断压进单张方法卡，有重新形成长提示词和答题模板的风险。用户因此要求改变试验单位：不再先寻找一张万能方法，而是让多个独立上下文分别承担专业推演。

这项方向变化不改写 A37 或 A49 的历史结论；它新增的是一个不同的架构候选。

## 五个专业板块

| 子 Agent | 负责什么 | 明确不负责什么 |
| --- | --- | --- |
| 定位专家 | IP 主体、赛道、人设、业务对象、价值承诺，以及商品名、品类和用户问题之间的语义层级 | 不替受众、内容、形式和商业化板块拍板 |
| 受众专家 | 目标受众假设、实际受众证据、观看与购买情境、动机和阻力 | 不用“宝妈”等人口标签直接推出固定需求 |
| 内容世界专家 | 母题、栏目、人物、事件、冲突、可持续系列和内容发动机 | 不把历史故事、真实案例等内容误写成表现形式 |
| 表现形式专家 | 口播、对话、采访、微短剧、情景剧、纪录跟拍、演示、纯素材视频和图文等表达选择 | 口播不得作为默认答案；历史故事不是表现形式 |
| 商业化专家 | 内容如何积累信任、触发行动、承接线索、成交、履约和复购 | 不补造价格、预算、渠道、客户、转化率或履约能力 |

平台适配、账号采集、MediaKit、浏览器发布、数据回收和复盘仍是完整 MCN 能力的一部分，但不是这次判断内核试验的第六到第十个决策角色。它们继续作为证据或执行能力，由孵化判断向下生长。

## 与第四版的边界

第四版的根问题不是“文件多”或“Agent 多”本身，而是多个提示词、中间件、工具、SOUL、阶段和测试同时拥有孵化控制权。本候选保留以下边界：

1. 五个子 Agent 只给板块简报，只有 Lead 面向用户并拥有唯一最终决策权。
2. 五个板块同时看同一项目，不按定位完成、受众完成、内容完成的顺序排成流水线。
3. 信息缺失时返回条件化判断和关键未知，不形成完整度硬门。
4. 不设角色投票、营销评分、通过阈值或多数意见。
5. 子 Agent 只读项目事实与证据，不共享写入记忆，也不能把专业意见提升为项目事实。
6. 内部共识不是市场证据，真实内容结果和经营结果仍是最终校准来源。

因此，这次是 manager / agents-as-tools 的专业分工试验，不是恢复第四版多控制器。

## 技术落点

`run_incubation_agent_eval.py` 新增隔离模式 `incubation-team`，直接复用 DeerFlow 的 `task`、自定义子 Agent、角色白名单、总委派上限、并发上限、超时、图步数、Token 预算和轨迹台账。

评测器复制宿主 `AppConfig` 并关闭通用记忆注入与写入；宿主对象不被修改。五个角色只允许：

- `incubation_project_context`
- `incubation_project_evidence`

角色禁用 `task`、`ask_clarification`、`present_files` 和 `incubation_record_subject_answer`，Skill 白名单为空，模型继承 Lead。每个角色必须显式设置独立图步数与 Token 上限，总委派上限固定为五次。

真实运行时一条模型消息最多保留三个并发 `task`，所以评测说明要求每批不超过三个，角色可按任意组合分批；分批只是技术并发限制，不代表业务先后。有效并发数显式传给嵌入式客户端，并写入实验清单和系统合同哈希，不依赖 DeerFlow 将来可能变化的默认值。

每个角色恰好调用一次是本次架构实验的操纵变量，用于避免再次出现 A37 的“角色存在但未触发”；它不是生产业务流程硬门。技术成功不再只依赖 Lead 最后有文本：评测器还会验证五个唯一角色、每个调用与结果配对、内部 `task_completed` 终态，以及每份委派提示绑定当前项目 ID。漏调、重复、未知角色、失败子任务、缺失结果或错误项目都会得到确定性失败码。

## 测试与验收

测试先失败于不存在的 `incubation-team`，实现后通过以下边界：

- 五个角色名称、顺序、专业职责、只读工具、禁用工具、无 Skill、模型继承、超时、图步数和 Token 预算被固定。
- Lead 提示词只展示五个专业角色，不暴露内置 `general-purpose` 或 `bash`。
- 评测说明明确内容与表现形式分离、并行板块、唯一 Lead 综合以及禁止投票、打分和直接拼接。
- 假流式端到端运行密封实验清单和实际五次唯一 `task` 调用。
- 原有单 Agent、内容世界消融和单证据研究员模式继续通过回归。
- DeerFlow 的 task 权限、Lead 提示组装、子 Agent 隔离和客户端配置回归通过。

真实 M01 首试使用以下标准复核：

1. 技术轨迹中五个不同角色各执行一次，并且没有写工具、递归委派或角色越权。
2. Lead 给出一个综合判断，而不是五份报告的目录或拼接。
3. 清楚区分定位、受众、内容、表现形式和商业化，不再把内容题材误称为形式。
4. 口播只能是有主体证据支持的候选，不能因“宝妈”标签成为默认路线。
5. 不补造主体能力、资产、渠道、产能、价格、预算或指标阈值。
6. 变现路径从已知产品或服务出发，并解释内容、信任、行动和成交的连接。

实际结果满足技术轨迹要求，并在内容/形式分离与非默认口播上改善；但违反第 5 项事实边界，商业化与产能判断建立在补造数字上。因此当前候选被业务拒绝。即使答案部分优于历史样本，也不能在没有同业务提示单 Lead 对照时宣称多 Agent 是原因。是否重新开启仍需匹配对照设计和用户确认。

## 第五版决定

1. 停止当前“继续蒸馏用户思维”的实现方向，保留 A49 只作为失败与局部信号证据。
2. 新增五板块 `incubation-team` 作为评测专用候选，不修改生产配置和生产 Lead 核心提示词。
3. 允许每个专业子 Agent 在自己的板块内作出有依据的判断，但禁止跨板块最终决策、写状态、提问、递归委派和不可逆操作。
4. Lead 继续拥有唯一最终决策权；不引入投票器、评分器、固定阶段、handoff 或第二 Agent 运行时。
5. M01 真实协作试验已技术通过、业务拒绝；不接生产、不自动扩大案例、不通过增加更多角色修补。若继续，先设计同业务提示的单 Lead 匹配对照，并让用户复核是否值得再次付费。
